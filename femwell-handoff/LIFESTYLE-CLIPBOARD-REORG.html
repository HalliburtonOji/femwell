2 · Why it reads "all over the place"

  1. Boards mix jobs. "For you" holds a shelf (editorial, saved) next to a doing-lens (try this). "Story & sky" holds a story + a planner action + an astrology door + a writing surface. A board isn't one room — so nothing has an obvious home.
  2. One content type lives in five places. Articles appear in the new Reads deck, For-you's editor pick, For-you's "more", Read/Articles, The-good-life's time picks, and Phase picks. Same for audio. She can't tell where "the articles" are.
  3. Two card languages on one page. The new deck is big FloraCover cards; every board lens is a cramped one-line ContentRow. The boards look like a list app bolted under a magazine.
  4. Density kills the cards. Up to 4 lenses per board (2 per shelf) leaves no room for a real cover — hence the tiles.
  5. Dead ends. Rows open a route or nothing; there's no in-place "look closer" — so browsing costs a full navigation every time.

3 · The reorganised boards

The rules (each fixes one problem above):

  • One board = one room = one job. Consume-shelves and do-shelves never share a shelf.
  • Every item is a cover-card (CoverCard + FloraCover) — no one-line rows anywhere on the clipboard.
  • Each shelf is a peek sub-slider (edge-peek + dots + subtle ‹ ›); uniform card size within a shelf (§6.7.0).
  • Tap = expand in place (the shared ExpandDetailCard), never a blind route. The route is the last step, from inside the expand.
  • Never empty — every shelf carries a seeded fallback (the deck's pattern).
  • One type, one home. The personalised "Reads for you" deck (already live, above the clipboard) owns "picked for you" — so the boards stop duplicating it.

5 · Before the live rebuild — two blockers on the shared component

Found while reading expandCards.jsx — both must be resolved or the rehome would REGRESS live behaviour (the boards' rows currently do real save + real open):

  1. Save is local-only. ExpandDetailCard holds const [saved, setSaved] = useState(false) — a demo toggle. Live it must be controlled: saved + onSave props, so it persists to UserProfile.saved_item_ids AND fires recordLifestyleAction (the piece-4 learning loop).
  2. Actions aren't wired. item.actions.map(...) renders buttons with no onClick — so "Read full" would do nothing. Needs actions[].onClick pass-through.

Both are small, additive, backward-compatible props (defaults keep the demos working). Owner: the brand session (it's their file) — or I add them additively once they've landed the variation set, coordinated via the baton so nothing is clobbered.
