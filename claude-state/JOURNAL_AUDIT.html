The Journal — audited end to end

Front + back + process + edge cases, before Community. Live bundle index--wKXIhLD.js. Method: 3 parallel deep-inspection passes (back-end / front-end / UX+edge) over the full Journal source, every finding then re-verified against the code, plus Playwright webkit renders. Genuinely critical — not a rubber-stamp.

Is it 100%? — No, not yet.

The core journaling surface is mature and genuinely well-built — compose, ledger, reader, search, Insights, Cycle Mirror, Sealed Letters, Echo and Witness all have real empty/loading/error states, the editorial token kit is strong, there is zero emoji anywhere, and the anonymity + on-device-crypto design is thoughtful. But the newest peer-to-peer features carry real risk: 3 Blockers and several High issues must be fixed before this is safe to put adults into community-style contact. The single biggest unknown is not in the repo at all — whether the Base44 entities are actually locked server-side (see B3).

Blocker ×3 High ×8 Medium ×11 Low ×6 Polish ×4

Must fix before Community

  1. Lock the peer entities server-side (Echo, WitnessRequest, WitnessStrike, TwinPair, TwinEntry): deny client read/write of others' rows; service-role only. The Echo wall proves clients currently have direct cross-user entity access — so the whole anonymity guarantee rests on out-of-repo config. Verify live that a direct client .filter() on each returns empty/forbidden. (B3 — the #1 item)
  2. Add crisis interception to Phase Twin — client (crisisCheck before postTwinEntry) and server (mirror in the function). It's the one peer surface with none. (B1)
  3. Fix the ZK "maximum privacy" key-delivery lifecycle so the receiver can't dead-end forever waiting for a writer who closed the app. Bounded wait + terminal state + opportunistic delivery on the writer's next app-open. (B2)
  4. Unify the mood lexicon — Insights mislabels every mood today (logs "Bright", reports "Angry"). (H2)
  5. Reconcile witness state against the server — clear a stale SENT_KEY that locks a writer out, and resume currentClaim() instead of always re-claiming. (H3, H4)
  6. Server-side Echo rate limit (the 5/day cap is client-only → floodable). (H5)
  7. Editorial cleanup — bring the sticky masthead onto tokens + a script title, and remove off-palette fills (gold pill, purple "dusk" card, espresso mood face, ledger rainbow). (H1, H6)
  8. Z-index discipline — one scale; the 18+ AgeGate must always sit on top before Community wraps a surface in it. (H8)

Blockers 3

Blockerback · privacy
B3 · Peer entities are directly client-accessible — anonymity rests on out-of-repo config
EchoWall.jsx:59,65,93,102 · base44/entities/*.jsonc (no permissions block)

The Echo wall reads every non-hidden row and updates/deletes rows it doesn't own (reactions, reports, hide, cleanup) via direct base44.entities.Echo.* calls — proving clients have cross-user entity access in this app. None of the anonymity entities (WitnessRequest/WitnessStrike/TwinPair/TwinEntry) declare access control in the repo, so a tampered client could in principle .filter() them and read every ciphertext, hash, wrapped_key and pairing — exactly the correlation the design forbids. The service functions are the privileged path but not the only path. Cannot be confirmed from the repo — needs a live authed probe.

Fix  Deny-by-default entity permissions (service-role only) checked into the repo; route Echo react/report through service functions; live-verify a direct client read of each entity is forbidden.
Blockerback · safety
B1 · Phase Twin delivers peer text with no crisis interception (client or server)
twin/PhaseTwin.jsx:handleShare · base44/functions/postTwinEntry/entry.ts

A daily twin answer is shared verbatim with the paired stranger, yet neither the client (handleShare posts raw draft.trim()) nor the server screens for crisis content — on a surface built for exactly the heavy disclosures (e.g. prompt d10 "what's taking up space you haven't said out loud"). Echo and Witness both gate on crisisCheck; Twin is the hole. This is safety-of-life, not privacy.

Fix  crisisCheck(draft) before posting (divert to UK resources like AskForWitnessSheet) + mirror the check server-side in postTwinEntry so a bypassed client can't deliver crisis text to a peer.
Blockeredge · process
B2 · ZK "maximum privacy" receiver dead-ends forever if the writer never returns
WitnessInbox.jsx (keypending stage) · AskForWitnessSheet.jsx (delivery only while sheet polls)

Under the opt-in ZK path the DEK is wrapped + delivered only by the writer's device, and only while AskForWitnessSheet is open and its 20s poller runs. The instant the writer taps "Done", delivery can never fire. The receiver who claimed sits in keypending ("this opens the moment it arrives") polling every 8s forever — no timeout, no terminal state, no pass-back. This is the inherent pull-pairing-ZK tradeoff we flagged at build time, but it is currently unhandled in the UI.

Fix  Bound the keypending wait to open_deadline/expires_at with an explicit "she hasn't handed her key — back in the pool" terminal state; move wrapping off the live sheet to a background reconcile on the writer's next app-open (scan rememberDek entries vs a published receiver_pub).

High 8

Highprocess · data
H2 · Insights mislabels every mood — two incompatible scales
JournalInsightsTab.jsx:14 (MOOD_MAP 1 Calm/2 Stressed/3 Low/4 Energized/5 Angry/6 Anxious) vs NewEntrySheet.jsx:107 (1 Low→5 Bright)

The composer only writes mood_rating 1–5 on a Low→Bright valence scale; Insights maps the same integers through a different 6-value lexicon. A user who logged Bright (5) sees "Angry"; Neutral (3) shows as "Low". The reader + Cycle Mirror use the correct scale, so the same entry is described two contradictory ways. Users will read this as the app being wrong about them.

Fix  One mood lexicon (1–5 Low→Bright) imported everywhere; drop the unused 6th value.
Highfront · brand
H1 · Sticky masthead runs on the legacy plum/mauve palette + a non-script title
Journal.jsx:103,112,118,129,134,135,144,150,156 (var(--plum/--mauve/--ivory/--surface/--border)); title :111 bare sans

The whole sticky header — title, dates, the Write CTA (a solid var(--plum) purple button), Hub button, season strip — is coloured with the app's old purple/mauve CSS vars, not T.* tokens, and the title "The Journal" is bare system-sans, not Ephesis. It's the first thing the eye hits and it clashes with the editorial byline directly beneath it.

Fix  Tokens throughout (ink/muted/paperDeep/paperHi, CTA = T.ink); render the title with <Script>.
Highfront · brand
H6 · Off-palette fills: gold pill, purple "dusk" card, espresso mood, ledger rainbow
Journal.jsx:200 (gold fill) · TonightReflection.jsx:21 (#2B2230→#3A2C30 purple) · NewEntrySheet.jsx:111 (#3A2C1A espresso "Bright") · JournalLedger.jsx:20 (14 indigo/teal/purple type hues)

Brand bans bright-gold fills, espresso-brown fills, and off-palette colour. The active wholeness filter pill is a solid gold block; the "Tonight" card is a violet-charcoal gradient; the brightest mood face is espresso; and the ledger encodes card type as an off-palette rainbow (also colour-only state, with a 10px label). These leak into the reader too via TYPE_COLOUR.

Fix  Active pill = ink fill / gold border only; add a single dark "dusk" token (no violet); brightest mood = ink; collapse ledger type colours to gold-hairline + ink label (reserve crimson for the one heart pop).
Highedge
H3 · Stale SENT_KEY strands the writer on a "Held by one sister" screen — locked out
AskForWitnessSheet.jsx:44 (existingSent → initial 'sent'), :297; witnessAnon.forgetSent

On open, any value in mySentId() jumps straight to the "sent" screen with no entry, then polls status. If that lookup fails or the row is gone, status stays null forever, "Take it back" never renders (no cancel_until), and — because it's 1 send/day — the user is locked out of Witness with a meaningless card. forgetSent() only fires on a successful cancel.

Fix  On restore, fetch real status first; if gone/failed, clear SENT_KEY and fall through to gate/confirm; always render a "Done/clear" affordance.
Highedge
H4 · WitnessInbox always re-claims instead of resuming the in-flight hold
WitnessInbox.jsx:118 (loading→claim()) vs witnessAnon.currentClaim (written, never read on load)

rememberClaim() is stored on every claim but never read on mount — the inbox unconditionally re-claims. A receiver who closes before responding can, on re-open, pull a second stranger's entry while the first is still assigned to her (or lose the one she held). The persisted claim id is dead code on the read path.

Fix  On load, if currentClaim() exists, re-fetch that request and resume; only claim anew when there's no live claim.
Highback · safety
H5 · Echo 5/day cap is client-only — the wall is floodable
base44/functions/postEcho/entry.ts (no count check) · echoAnon.js bumpEchoesToday (localStorage)

postEcho does crisis + length checks but never counts the author_hash's prior echoes; the daily cap lives only in localStorage. A scripted or storage-cleared client can flood the lightest-moderation peer surface unbounded. postWitnessRequest correctly enforces 1/day server-side — Echo should match.

Fix  Count Echo.filter({author_hash}) since start-of-day in postEcho; return {error:'rate'} past the cap.
Highedge
H7 · Insights tab has no loading/error state + an uncaught Promise.all
JournalInsightsTab.jsx:43 (DailyCheckins/CycleEvents fetch, no try/catch, no loading flag)

The overlay renders while data is still empty (cards flash "keep logging to unlock" then pop), and the Promise.all has no .catch — a rejected request throws unhandled and cards silently stay empty, looking broken. Unlike the parent page + SealedLettersSection, there's no error fallback.

Fix  Loading skeleton + a .catch setting a "couldn't load your insights" state.
Highfront · a11y
H8 · Z-index ladder is incoherent — the 18+ AgeGate isn't guaranteed on top
AgeGate.jsx:25 (z 90) = NewEntrySheet.jsx:348 (z 90) < SealedLetterCompose.jsx:72 (z 92); child sheets nested below parents

The overlay stack is unsorted (Echo/Twin/Witness 60, EntryReader 70, Insights 75, FourLives/Hub/Sealed 80, NewEntry 90, SealedCompose 92, AgeGate 90), and child sheets render inside higher-z parents (their value only "works" by DOM order). A safety boundary (AgeGate) below a composer is wrong; any refactor will mis-stack.

Fix  A single Z scale in Editorial (sheet/modal/gate); AgeGate at the top, non-dismissible by backdrop.

What's genuinely solid

  • Anonymity model — every peer write is asServiceRole (created_by = service, never a user id); device-derived hashes in separate namespaces (echo::/witness::/twin::, distinct secrets) with no cross-surface correlation.
  • Witness zero-knowledge (FWWT2) is correctly keyless at rest — DEK never reaches the server, wrapped to the receiver's ECDH P-256 key post-claim; FWWT1 + pre-encryption plaintext both still open (clean version detection, additive fields).
  • Crisis interception is consistently wired on Echo + Witness (re-checked on send, diverts to correct UK resources — Samaritans 116 123 / NHS 111 / Shout 85258 / Mind), never posting. (Twin is the gap — B1.)
  • Empty / loading / error states are real on the parent page, Echo Wall, Sealed Letters, Search and BreakSeal; cold-start + no-results copy is on-brand. The honest "sealed on another device, key never left it" message is exactly right.
  • Editorial token kit (T / Script / Hand / Eyebrow / Rule / ink-carve) is well-built and mostly consumed cleanly; zero emoji anywhere; layouts fluid at 390px with no fixed widths over ~360px.
  • On-device privacy framing (scrub → encrypt → "never leaves the device") is consistent; long-entry caps (1200 chars, 600-char previews) respected in Witness/Twin.
