Rituals — a practice garden, not a streak

Short phase-tagged practices she voluntarily adopts. Tea on luteal day 2. Four-seven-eight before bed in follicular. Iron-rich breakfast on period day 1. They grow a visible ritual garden — a living thing, not a scoreboard. Skipping a week just means a leaf rests. Jess proposes one ritual per phase based on data; she keeps or discards. This is the feature that resolves the tension between "we don't do streaks" and "we need retention."

What it is
A living garden of practices
Each ritual becomes a plant. Thriving = rose bloom. Steady = green leaf. Resting = dormant bulb. Sprouting = gold bud.
How it stays
Jess proposes one per phase
Not ten at once. One ritual per cycle phase, data-justified. The user keeps, adjusts, or discards. No defaults — every plant in the garden was chosen.
What it refuses
Zero streak surface area
No day count. No "X weeks in a row." No failure state. Skipping = rest, not break. A ritual at rest can return in a season; it never dies.
Why it works
Retention through ownership
Competitors force habits on users and call it discipline. FemWell waits until you claim a practice. You don't ditch what you planted.

Engineering spec — Rituals

Adds a first-class practice garden surface with three thin new entities + a proposer job. All rituals are user-chosen, data-justified, and reversible without penalty. Ties into the existing PracticeSeasons entity from the Garden palette library so a user's ritual garden shape maps to their current season.

New entities (base44)

Rituals (template)

  • id uuid
  • name string — "Magnesium glycinate", "4-7-8 before bed"
  • category enum: supplement / breath / movement / food / journal / light / sleep
  • phase_tag enum[]: period / follicular / ovulatory / luteal (a ritual may span multiple)
  • cycle_day_window json — e.g. {from:18,to:20} or {phase:"luteal",anchor:"evening"}
  • evidence string — short human-readable justification
  • evidence_urls string[] — DOI/PubMed/guideline links
  • contraindications string[] — "pregnancy", "kidney disease", "SSRI", etc.
  • glyph_shape enum: bloom / leaf / sprout / bulb / candle — drives garden visual

RitualAdoptions (user ↔ ritual)

  • id uuid
  • user_id fk
  • ritual_id fk
  • adopted_at ts
  • custom_when json — overrides template's cycle_day_window
  • custom_time string — "21:00"
  • season_length_cycles int — 1 / 3 / forever
  • nudge_mode enum: silent / gentle_single / morning_of
  • origin enum: jess_proposed / user_added / onboarding_seed
  • jess_why json — signals that justified the proposal (shown in Adopt flow)
  • uproot_at ts nullable — soft-delete, history preserved

RitualStates (the living signal)

  • id uuid
  • adoption_id fk RitualAdoptions
  • week_index int (since adoption)
  • cycle_index int (which cycle since adoption)
  • state enum: sprouting (first 2 weeks) / steady (≥ 50% tends, weeks 3+) / thriving (≥ 80% tends, weeks 3+) / resting (< 20% tends over last 2 weeks)
  • tend_events int — number of times marked done this week
  • notes string — optional user notes about this week
  • state_changed_at ts

RitualTendEvents (single "I did it")

  • id uuid
  • adoption_id fk
  • tended_at ts
  • phase_band enum — cached for stats
  • cycle_day int — cached
  • source enum: user_tap / auto_inferred (via Pulse data) / jess_prompt
  • felt_sense enum nullable: lifted / same / softer / tender — the optional afterglow tag

State machine — the plant's life

sprouting     first 2 weeks after adoption                         gold bud
steady        weeks 3+ AND ≥50% of expected tends last 2 weeks    green leaf
thriving      weeks 3+ AND ≥80% of expected tends last 2 weeks    rose bloom
resting       weeks 3+ AND <20% of expected tends last 2 weeks    dormant bulb

rest → steady:    re-enters on 2 consecutive expected tends
rest → uprooted:  only if user explicitly uproots. never auto-removed.
never: broken, failed, lapsed, expired. those words don't exist in the UI.

Jess proposer — how a ritual gets suggested

  • Signals: 3+ cycles of Pulse data, Journal topics (last 30d), Sessions plays, existing symptoms. Need phase-correlated pattern with ≥3-cycle consistency.
  • Threshold: proposer only fires when Jess has ≥75% confidence the ritual would help this user specifically (based on pattern strength + literature match).
  • Rate: one proposal per 14 days maximum. Never more than one open proposal at a time.
  • Evidence-first: every Jess-proposed ritual must link to ≥1 RCT/guideline. No "might help." No "some women find."
  • Contraindication check: screens against user's Care Bridge-logged meds + conditions. Defers to Care Bridge if uncertain.
  • Refusal-safe framing: the Adopt card always includes "pass" equally weighted with "keep". Passing generates no follow-up nudge for ≥30 days on that ritual.

Garden rendering — from state to shape

plant.position_x = user.garden_layout.order[adoption_id]
plant.height     = adoption.age_weeks * 4px  (capped at 80px)
plant.bloom      = (state == "thriving") ? 34px rose bloom
plant.leaf       = (state == "steady")   ? 30px green leaf
plant.bulb       = (state == "resting")  ? 22px dormant bulb, stem 60% opacity
plant.sprout     = (state == "sprouting") ? 16px gold bud, smaller stem
plant.pulse      = (state == "thriving" AND tended_today) ? animated ring

garden.backdrop  = user.current_season.gradient (from Garden palette library)
garden.soil      = cream→soil gradient, constant
garden.caption   = "season · {season.name}" + "week N of 12"

Ties to other systems

  • Garden palette library — each ritual plant sits on the season backdrop; the garden tile-shape matches the season tile (hex, dot, square, etc).
  • Smart Nudges — ritual-triggered nudges go through the same earned-push pipeline; never a batch schedule.
  • Journal — tend events can be auto-logged from Journal entries ("had ginger tea" inferred), but only with explicit Ritual-inference opt-in.
  • Pulse — wearable-inferred tends (e.g. breath sessions detected from HRV spike) are opt-in, always confirmable.
  • Today — "2 rituals are ready" card on Today surfaces today's due rituals, respecting nudge_mode.
  • Profile Seasons — completed 12-week seasons show the ritual garden as it was, preserved.

Ship order

  • Q3 2026 — Garden home (P1) + manual tend events + hand-curated starter rituals. No Jess proposer. User-added only.
  • Q4 2026 — Jess proposer (P2) + adjust flow + contraindication engine (reads Care Bridge meds).
  • Q1 2027 — Detail + rest states (P3) + graceful resume options + "softer return" variants.
  • Q2 2027 — Season stats (P4) + per-cycle view + Jess season reflection draft.
  • Q3 2027 — auto-inference from Pulse/Journal (opt-in), Partner Sync integration (show "what helps today" sourced from thriving rituals).

What Rituals will never have

  • Streaks. No day counter, no "X days in a row", no "streak broken" state, no "best streak" leaderboard.
  • Badges or XP. No levels, no trophies, no unlocks tied to consistency.
  • Compare-to-others. No "80% of women in your phase do this." The garden is entirely private.
  • Public sharing. No share-your-garden feature. Ever. (Partner Sync can surface "what helps" — that's the ceiling.)
  • Red / failure states. Resting uses plum-soft. Uprooting is a gentle, neutral action. No guilt in the palette.
  • Auto-add rituals at onboarding. New users start with an empty garden. Every plant is chosen.
  • Proposer spam. One proposal per 14 days. Passing a proposal silences that ritual for 30+ days.
  • Medical prescribing. Rituals can be supplements or food, but never prescription medication. Those route to Care Bridge.
