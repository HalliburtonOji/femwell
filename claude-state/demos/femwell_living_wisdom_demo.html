Living Wisdom — Echo Wall × Jess flywheel

Every Echo on Community is an atomic piece of collective wisdom. Jess surfaces one at the contextually right moment — as company, not advice. Luteal d19, writing about sleep, she'll show one faded Echo another luteal-d19 user wrote with 42 holds. No names. No fix. Just "someone is here too." This is the flywheel competitors can't replicate — the more Echoes, the better the surfacing, the more reason to stay.

Principle 1
Atomic wisdom, never prescriptive
An Echo is one sentence, same-phase, anonymous. Jess never wraps it in "try this." She frames it as company: "someone 19 days in wrote this."
Principle 2
Phase + topic + hold-weight
Surfacing math is phase-match × topic-match × recency × holds. Never a trending feed. Held Echoes rise; scrolled-past ones fade.
Principle 3
Never-repeat, user-scoped
Once Jess has shown you an Echo, she won't show it again for 90 days. JessWisdomSurfacings logs every surface so the same line can't re-appear stale.
Principle 4
Compounds quietly, never pushed
Wisdom surfaces only inside moments she's already in — journaling, Today, Panic afterglow. Never a push notification. Never an Explore shelf.

How Jess
chooses an echo

Every rule you see is a rule you can turn off. No hidden ranking.

1 · your phase right now
Echoes are phase-tagged by the writer. Jess only considers ones that match your current cycle day ±2.
must match ± 2 days
2 · your recent topics
What you've journaled about in the last 7 days. Sleep, mood, work, body, relationships, boundaries, rest. Derived from your own words — never shared back.
weight × 3 7-day window your data only
3 · hold weight
How many other users held that Echo (anonymous agree). No likes. No reactions. Held = "this is true for me too." Min threshold: 5 holds.
weight × 2 min 5 holds no likes
4 · recency + decay
Echoes fade over 90 days. A 3-day-old Echo with 12 holds can beat a 60-day-old one with 40 holds. Keeps wisdom current, not ossified.
linear decay 90-day half-life
5 · never-repeat
Once you've seen an Echo (shown, not just scrolled past), Jess won't show it again for 90 days. Prevents drift into muzak.
90d lockout per user
6 · what's never shown
Echoes flagged by 3-strike witness policy. Echoes from users you've muted. Echoes about medical prescribing (Jess routes those to Care Bridge instead). Anything containing phone numbers, URLs, or identifiable detail.
flagged muted-author medical identifying
Your control
You can turn all of this off
One switch in Settings → Jess → Living Wisdom. If it's off, you'll never see an Echo surface again. Your contributions stay on the wall for others, unless you mute those too.

Engineering spec — Living Wisdom

Reuses the Echoes + EchoHolds tables already built for Community v2 (Q2 rollout). Adds two thin new ones + a surfacing job. Zero new user-facing writes. Wisdom is a surfacing layer on top of existing content.

New entities (base44)

WisdomIndex

  • id uuid
  • echo_id fk Echoes
  • phase_band enum: period / follicular / ovulatory / luteal
  • phase_day int 1-35 (writer's cycle day at post)
  • topic_tags string[] (derived: sleep, rest, work, body, mood, boundaries, relationships, self-compassion, anxiety, grief)
  • hold_count_snapshot int (denormalised for ranking speed, refreshed 6h)
  • age_days computed from echoes.created_at
  • flag_state enum: clean / muted / medical / identifying
  • eligible bool = (flag_state=clean AND hold_count ≥ 5 AND age_days ≤ 180)

JessWisdomSurfacings

  • id uuid
  • user_id fk Users
  • echo_id fk Echoes
  • surface enum: journal / today / panic_afterglow / jess_drawer
  • shown_at ts (append-only)
  • matched_on json (ranking signals — phase/topic/holds/decay — kept for transparency panel)
  • user_action enum: held / saved / passed / hidden / null (null = not acted on)
  • lockout_until ts = shown_at + 90 days (the never-repeat horizon)
  • scroll_depth_ignored bool (true = flush through, doesn't count as "shown")

Ranking function

score(echo, user) =
    3.0 × phase_match(echo.phase_band, user.phase_band)     // must be ±2 cycle days
  + 3.0 × topic_match(echo.topic_tags, user.recent_topics)  // Jaccard over 7-day topic set
  + 2.0 × hold_weight(echo.hold_count_snapshot)             // log-scaled
  + 1.0 × recency(echo.age_days)                            // linear decay over 90d
  - ∞   if has_been_surfaced_within_90d(echo, user)         // never-repeat hard gate
  - ∞   if echo.flag_state != clean
  - ∞   if user has muted echo.author_id
  - ∞   if user has topic or phase disabled in JessWisdomPolicy

Where it surfaces (and where it doesn't)

Surfaces where wisdom can appear

  • Journal compose — trigger: 60s of sustained writing + phase/topic match ≥ threshold → one faded wisdom card inline. Max 1 per writing session.
  • Today morning hero — trigger: first Today open between 06:00–09:30 + fresh unshown echo available. Max 1 per day.
  • Panic afterglow — trigger: Jess-noticed card in afterglow if a relevant held echo exists on "panic + luteal" or matching phase. Opt-in — off by default after panic.
  • Jess drawer — "more like this one" when user holds a wisdom card they liked.

Surfaces where wisdom MUST NOT appear

  • Push notifications — never. Wisdom doesn't ring phones.
  • Explore / content shelves — never. Explore is credentialed content only.
  • Community main feed — echoes already live there; wisdom is the targeted surface, not a re-shuffle of it.
  • Partner Sync — partner never sees your wisdom surfaces.
  • Care Bridge clinician portal — clinicians never see echoes or surfacings.
  • During Panic Mode itself — panic is not the moment for other voices; only in afterglow if opt-in.
  • Onboarding — new users get no wisdom for first 14 days. Let their own phase form first.

UK GDPR + DPA 2018 + consent posture

  • All ranking is computed server-side per request. User topics are derived from journal (never shared), fed as ephemeral signals, not stored on the Echo side.
  • JessWisdomSurfacings.matched_on is the audit object the transparency panel reads. Never batch-queried for analytics — per-user only.
  • User can mute: any author, any topic, any phase, any surface, or the whole feature. Muting is instant and propagates to future surfacings within ≤ 15s.
  • Never auto-train on hold data for content generation. Holds are ranking signals only; the wisdom is user-authored.
  • No model fine-tune on user echoes. No third-party data export. Wisdom stays inside the wall.

Flywheel — why this compounds

Month 1: ~500 echoes → surfacing quality is rough, phase clusters thin. Month 6: ~10,000 echoes with density in every phase × topic cell → surfacing is always there. Month 12: the wall is a living reference of what every phase feels like. The moat: no new app can launch with this volume of real same-phase wisdom. It's the product feature that literally cannot be built on day one.

Ship order

  • Q3 2026 — WisdomIndex + Journal surface only. 1 surface, 1 phase (luteal), observation mode. Hold-counts tracked but no transparency panel yet.
  • Q4 2026 — Today hero surface + full phase coverage + transparency panel (P3).
  • Q1 2027 — Panic-afterglow surface (opt-in) + Wisdom index browse (P4) + per-author/topic/phase mutes.
  • Q2 2027 — Jess drawer "more like this" + cross-phase learning ("you held 3 rest-themed echoes, your next luteal will default to rest-weighted").

What we are not building

  • No author profiles. Echoes are anonymous by foundation; there is no "wisest user" metric.
  • No daily wisdom push. Wisdom arrives inside moments; it doesn't summon you.
  • No curator-picked wisdom. FemWell staff do not hand-select echoes. Only hold-rank + never-repeat.
  • No wisdom sharing out. You cannot screenshot or export an echo surfaced to you. (Respect for the writer.)
  • No advice framing, ever. Copy is always company — "someone wrote this" — never "try this."
