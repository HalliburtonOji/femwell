Smart Nudges — every push earns its send

Not calendar-based. Not cohort-average. Every push is justified by your data. Magnesium on luteal day 22 — only if your sleep has been poor this cycle. Iron on period day 1 — only if last cycle was heavy. "Bed early tonight or luteal tomorrow will cost you" — only when HRV trend predicts it. If no signal, no send. Silence is the default.

Principle 1
Signal-triggered, never scheduled
Rules fire when user data crosses a threshold. No "9am supplement reminder" unless today's data says it matters. Absent signal = no push.
Principle 2
Every nudge shows its work
Tap any nudge → why this, why now. Full signal list. Evidence link. Rule ID. If Jess can't explain it in plain English, she can't send it.
Principle 3
Per-category snooze, instant
Supplement pushes, sleep pushes, food pushes, care pushes, ritual pushes — each muted independently. One tap to silence; mute lasts as long as user sets (cycle / 3 / forever).
Principle 4
Budget of 3 per day, cap of 10 per week
No exceptions. If a fourth rule earns send today, it waits for tomorrow. Quiet hours are hard. Panic Mode bypasses all caps.

Engineering spec — Smart Nudges

A rules engine + outbox, not a notifications service. Rules are human-written (clinician + engineering review), versioned, evidence-linked. The engine evaluates every rule against user signals on a 15-min cadence and on explicit triggers; only rules that earn send reach the push outbox. Every send is logged with full signal snapshot.

New entities (base44)

NudgeRules (template library)

  • id string — stable rule key, e.g. SOFT_MORNING_LOW_SLEEP_LUTEAL
  • version int — bumped on any condition or copy change
  • category enum: sleep / supplement / food / ritual / care / rest
  • name string — plain-English name
  • conditions json-dsl — structured if/and/or tree over allowed signals
  • copy_template string — includes substitutions {{sleep_total}}, {{phase_day}}
  • evidence_links string[] — DOI/PubMed/clinical-guideline URLs
  • author string — clinician who drafted copy
  • cooldown_hours int — min gap between same-rule fires for same user
  • default_channel enum: push / in_app_only / silent
  • requires_opt_in bool — true for panic-related, aggressive-care rules

UserNudgePolicy (per user)

  • user_id fk
  • global_enabled bool — master switch
  • category_states json — e.g. {"sleep":"on","food":"silent","supplement":"gentle"}
  • per_rule_overrides json — disable/tighten specific rules
  • quiet_hours json — e.g. {"start":"22:30","end":"07:00"}
  • daily_budget int default 3
  • weekly_budget int default 10
  • learning_enabled bool — whether "did it help?" answers adjust weights
  • opted_in_rules string[] — explicit opt-ins for care/panic/aggressive

NudgeEvaluations (the "considered" log)

  • id uuid
  • user_id fk
  • rule_id fk NudgeRules
  • rule_version int
  • evaluated_at ts
  • decision enum: sent / suppressed
  • suppress_reason enum nullable: threshold_not_met / category_muted / rule_disabled / quiet_hours / daily_budget / weekly_budget / cooldown / requires_opt_in
  • signals_snapshot json — denormalised signals used by condition evaluation
  • copy_rendered string nullable — only if decision=sent
  • push_id fk nullable — push outbox record if sent

NudgeFeedback (post-nudge felt sense)

  • id uuid
  • evaluation_id fk NudgeEvaluations
  • answered_at ts
  • felt_sense enum: lifted / softer / same / not_for_me
  • one_word string nullable (optional free-text, never shown to anyone else)
  • action_taken enum: enabled_auto / tightened_rule / muted_rule / nothing
  • applied_to_policy bool — did this feedback change UserNudgePolicy

Rule condition DSL (signals allowed)

// Conditions are structured — never free-form LLM evaluation.
{
  "all": [
    { "signal": "sleep_total",  "op": "<", "value": "baseline − 1h" },
    { "signal": "hrv_delta_7d", "op": "<", "value": "-5%" },
    { "signal": "phase_band",    "op": "==", "value": "luteal" }
  ]
}

Allowed signals (read-only, derived from Pulse/Cycle/Journal):
  phase_band, phase_day, cycle_day, bleed_intensity_last, bleed_flow_today,
  sleep_total, sleep_onset, sleep_baseline, hrv_now, hrv_delta_7d, hrv_trend,
  rhr_now, rhr_delta_7d, journal_topics_7d, panic_count_cycle, panic_count_30d,
  ritual_due_today[], ritual_state[], care_bridge_days_to_expiry,
  care_bridge_preview_viewed, time_of_day, locale, opted_in_rules

Disallowed in conditions:
  user PII, user name, user pronouns, any other user's data,
  step count, body weight, body fat, BMI, sexual activity,
  partner data, clinician notes, journal content (only derived topics)

Evaluation cadence

  • 15-min cron — every user × every enabled rule evaluated. ~40 rules × 100k users = 40M evaluations/day (manageable in base44 cron).
  • Event triggers — immediate eval on wearable sync, cycle state change, panic log, Care Bridge state change.
  • Budget gate — before outbox, check user's daily_budget and weekly_budget. Panic-related and Care-Bridge-expiry bypass daily budget, never weekly.
  • Cooldown gate — per-rule cooldown prevents chatter (min 3h; most rules 24h).
  • Quiet hours gate — hard; sends delayed to window_end unless rule marked urgent.

Learning loop (Principle 5)

Feedback adjusts rule weights per user only, never globally. If a user marks "softer-morning" rule as Lifted 3× at HRV −5%, the threshold tightens for them to −4% next time. If they mark it Not for me 2×, the rule disables itself for them and surfaces a "we won't fire this again" note.

per_user_rule_weight = base_weight
  + (lifted_count × 0.10)
  + (softer_count × 0.05)
  - (same_count × 0.02)
  - (not_for_me_count × 0.50)  // strong downweight

if per_user_rule_weight < -0.50 → auto-mute rule for user, surface toast in-app

What Smart Nudges will never be

  • Scheduled pushes. No "8am daily wellness reminder." Rules fire from signals, not clocks.
  • Growth-driven. Rules are not tuned for DAU/retention. Helpful-rate is the only engagement metric; it is reported to users, not A/B optimised.
  • LLM-authored copy at send time. Rules ship with clinician-written templates. Signal substitutions only. No runtime generation.
  • Cross-user "women like you" aggregations. Every rule's signals are yours only.
  • Panic-Mode without opt-in. Every panic-related rule requires explicit user opt-in; turning off is instant.
  • Medical prescribing. Nudges never introduce new prescription medication. Those route to Care Bridge as "talk to your clinician."
  • Marketing or upsell. Nudges are about care, never Pro conversions or referral asks.
  • Partner-visible. Partner Sync cannot see your nudge list or feedback.
  • Un-editable. Every rule is individually toggleable. Every category is individually muteable. The global off-switch is real.
