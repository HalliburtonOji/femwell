Why two tabs · the split logic

The single-scroll Phase 2 demo carried 9 new Phase-2 mechanics + the full canvas on one screen — easily 14+ vertical sections. Decision fatigue. Two tabs by time horizon resolves it without removing any content. Today = the next 24 hours, what to do and when. Cycle = the bigger arc, where I am and where I'm headed.

SectionLives onWhy
Fresh-Start bannerTodayTriggered by today's event (cycle day 1, fresh Monday) — invitation to act now.

Good-for chipsTodayCapacity-composite, scoped to this day.

Cross-tab links (so the split doesn't strand the user)

Two affordances stitch the tabs together so nothing feels orphaned:

  • From Today → Cycle: Tonight's Window's "Share this week with my GP" deep-links to the Doctor-Ready Diary on Cycle.
  • From Cycle → Today: Tapping any day in the Month ribbon re-targets the Today tab and switches view. The Capacity Tax "Defer 3" pill returns the user to Today with a "3 items moved" toast.

MP impact

The two-tab split is scope-light, layout-heavy. The 9 Phase-2 mechanics + 9-commit Planner-A sequence in spec_v2.md still apply — each commit ships the same surface to the same tab. One small commit added to the top of the queue:

  • MP-A0 · Tab shell + routing. Segmented control component, sticky at top of /planner. URL state: ?view=today (default) | ?view=cycle. Today's view ID maps to existing Planner page; new PlannerCycleView component mounts the Cycle-tab sections. Cross-tab deep links pass ?view=cycle&scrollTo=doctor or ?view=today. Persist last-viewed tab in localStorage so the user lands where they left.

C1-C9 build under MP-A0, but each commit knows which tab its surface belongs to. Acceptance: 3-viewport walk on both tabs after each commit.
