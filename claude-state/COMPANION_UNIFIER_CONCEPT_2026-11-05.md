# FemWell · the companion who lives in the garden

**Status:** Ideas concept, 5 November 2026. No character, new memory, voice default or social behaviour has shipped from this note. Halli asked to adapt the recent “Brainstorm RealLife app concept” exchange, especially its funny customisable buddy, visible reactions, interactive objects and shared history. This is a FemWell proposal, not a RealLife pivot.

## First pass (superseded as the sole direction)

**Let the existing Jess become a visible, playable garden resident.** The approved accumulating garden remains the record of her life; Jess is the actor who moves through it and visits the rooms of the app. Keep the existing named bloom companion and its form, personality, tend, share and chapter history. Do not create a second AI agent or make a full-screen game the price of opening an article. A user avatar or separate pet can be an optional later concept after one character proves useful.

The first test proposed one 60–90 second meeting-practice scene. It is still a useful candidate, but Halli judged this single-character answer too narrow. The second exploration below broadens the world, cast and everyday life before choosing a first demo. No design is approved by this document.

## One relationship across existing rooms

| Existing owner | Jess's compact role | Real destination or return |
|---|---|---|
| Today | One relevant invitation, never another feed or mandatory greeting | Exact Planner, Read or Garden object |
| Lifestyle Read / Books | Holds a bookmark or reacts to an exact saved passage; optional one-line comment | Existing reader, Save, Continue, book shelf |
| Listen / Sky | Quiet presence during playback or a single authored sky story | Existing player/transcript and Sky source |
| Good life | A two-minute shared action such as getting out the door or handling one small admin step | Existing room action and Planner when user asks |
| Jess | Same named persona and voice preference, with text-only and silent options | Existing chat/history/settings/memory and action envelope |
| Garden | Home for the character and visible objects earned from actual actions | Existing accumulating plants, chapters, rename/reshape/share |
| Community | Optional hand-off to an actual room only on user request | Existing anonymous consent and exact Community return; no automatic post or DM |

Interaction grammar: **notice → react → offer → do → show receipt → remember only if chosen**. The character can turn, pause, fumble an object, smile and recover; she need not speak at every step. “Not now” closes the moment with no guilt. An optional saved memory can be inspected, edited and forgotten in the existing Jess memory UI. Never pretend the character observed off-app events or private DMs.

## Implementation shape and cost gate

First prototype: a small 2D rig or authored sprite with a few purposeful states (idle, attend, speak, interrupted, pleased, quiet) and botanical prop interactions. Draw it into a **single contained Ideas scene**, then a compact, non-blocking version only if Halli likes it. Reuse `jess_name`, `jess_character`, `jess_proactivity`, `jess_privacy`, `JessMemory`, the existing action executor, `CompanionState`, garden chapters and actual Planner/Read IDs. Map ownership and resolve the two existing names before any profile/schema migration. No new Base44 function name. Do not call an LLM for every blink, page view or motion; client events drive animation. Interactive Jess calls occur only on explicit conversation. Reuse authored audio assets when approved; no per-view TTS. Measure cold/return JS bytes, animation frame cost, requests and paid units, with low-motion, silent and text-only paths. MDN notes that animation properties and media size can affect performance, and `prefers-reduced-motion` should reduce nonessential motion: [animation performance](https://developer.mozilla.org/en-US/docs/Web/Performance/Guides/Animation_performance_and_frame_rate), [reduced motion](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/prefers-reduced-motion). The [Generative Agents research](https://research.google/pubs/generative-agents-interactive-simulacra-of-human-behavior/) suggests observation, memory and planning contribute to believable agents; for FemWell, keep the remembered observations explicit and user-controlled. [NVIDIA ACE](https://developer.nvidia.com/ace-for-games) demonstrates speech/animation/game-character components, but its game stack is not assumed to fit this Base44 web app.

## Second exploration — a place, a cast, and useful consequences

**Correction from Halli, 5 November:** the first proposal felt like putting an animated Jess onto the current app. It did not go far enough into game feel, characters reacting to each other, surprising everyday uses or what makes the app one world. Inspecting signed-in Today and Garden reinforces that criticism. Today already has a greeting, Jess text, a task list, a loop, cross-day cards and another Jess observation; Garden has its own named bloom, chapters and social meadow. Another character card or floating control would crowd the screen. The app needs a *grammar of interaction* carried through existing destinations, not another feed.

### Four genuinely different worlds to test

| Direction | What she actually sees/does | What makes it different | Failure to guard against |
|---|---|---|---|
| **Living Margins** | A hand-drawn Jess lives at the edge of an editorial page. She folds a corner of a real saved article, passes a bookmark into Books, perches on the moon dial in Sky and leaves the page when reading starts. Her gestures have a job; text and source remain primary. | Magazine craft becomes movement, rather than a game pasted over a magazine. One-tap content still works. | Too much waving, tiny controls, or an expensive full-page animation on every route. |
| **Garden Atelier** | An optional illustrated tabletop/garden is a place to return to: moon clock, book, small envelope, tea cup, worn ticket, seed packet. Objects are *her actual saved things* and open their source. The garden grows in response to chosen records, never a daily check-in quota. | Existing accumulating plants and chapters become an inhabitable memory, without replacing the normal tabs. Props can cross rooms. | A toy house with dead props, fabricated history, a second navigation maze, or compulsory tending. |
| **Jess + Bloom** | Jess is the speaking, interruptible helper; the already named bloom companion is a mostly wordless witness with its existing name/form/personality. Jess may offer a plan; the bloom uncurls when the user keeps a line or saves a page. They sometimes notice each other. Both can be hidden independently in a scene. | Two different presences create relationship and comic timing without another AI persona. The bloom remembers *chosen* moments without pretending to know the user's mind. | Merging or overwriting either existing identity, needy-pet guilt, automatic disclosure to Garden/Meadow. |
| **Everyday Theatre** | Optional 30–90 second playable scenes: practise a boundary, deal with a letter, recover a derailed day, decide what to do with a free hour. Jess can take a role, pause, be interrupted and hand over a real draft, plan or source. | The user *does* something with a character; the scene produces a useful outcome, not a badge. | Generic therapy scripts, invented personal facts, endless dialogue, or sending messages without consent. |

**Working synthesis for the first visual demo, not a main-page decision:** Living Margins is the behaviour across ordinary pages; Garden Atelier is an optional home; Jess + Bloom is the cast; Everyday Theatre is the deeper activity when invited. They share one event/source model. This gives a playful world with a normal, quick app underneath. Explore visually whether this synthesis is coherent before committing to it. The real-life chat's optional user avatar remains an alternative: a user's likeness and motion could be powerful in rehearsal, but representation, body/image data and rendering cost deserve a separate concrete prototype, not an assumed default.

### Five scenes to challenge the design, beyond the meeting

1. **The day fell sideways.** A real Planner item slips; Jess catches a paper plan card but does not assume why. She offers “Keep one thing,” “Move the rest” and “Leave it.” The user sees the exact proposed changes and confirms before any Planner write. The bloom can lie quiet beside the re-folded card. On return, the card opens the changed item. No false resilience speech, no points for coping.
2. **The letter on the table.** In Good life Money, the user explicitly chooses a real letter/task. Jess turns an envelope over: “What is due?”, “Who is asking?”, “Where is the source?” She can help draft a question, but a source-backed guide and the original task remain one tap away. No autonomous financial advice or payment. If saved, the envelope is a private object with a deadline and exact source, never an AI-generated claim that a bill is resolved.
3. **A free Friday with no grand transformation.** Today knows an open window only from actual Planner data. Jess presents two genuinely available choices from the reviewed Read/Listen/Outside catalogue and a “Surprise me” shuffle. The scene ends at the episode/article/action in one tap. An unavailable stream swaps to its truthful source page; no 20-second video masquerades as a full listen.
4. **The unsent invitation.** A saved Books passage or Community club conversation gives a reason to reconnect. Jess offers to draft “Fancy reading this with me?” as a private draft. The user chooses whether to copy, edit or discard; there is no auto-DM, public reveal or implied knowledge of someone else's feelings. A chosen bookmark can return to the exact passage and optional club, respecting spoiler position.
5. **The moon kitchen.** Sky's moon clock and morning-glory tissue become a small stage. Jess tells a short, wry *authored* sky anecdote and can be interrupted for “What does that mean?” or “Show me tonight.” The bloom responds to the lamp/moonlight without pretending lunar phase predicts an individual event. The cited astronomy source and the person's actual chart (when provided) remain separate and directly reachable.

**The meeting rehearsal remains a sixth test**, especially for turn-taking, but should not be the only demonstration of the concept. The first visual storyboard should compare a useful recovery scene with a playful curiosity scene; if both feel like the same template with different copy, the design has failed.

### Small mechanics that could make this feel like *her* world

- **A room remembers the object, not the lecture.** A finished book leaves a bent bookmark on the atelier table. A saved sky bulletin leaves one pressed night flower beside the moon clock. On tap, the real item opens directly; the object is a shortcut and a memory cue, not an extra achievement screen.
- **Inside jokes are user-editable, never guessed.** If she names an admin task “the admin goblin,” Jess may reuse it once in that context. A visible “Forget that” removes the joke. Nothing from a DM or private Community room enters this memory by implication.
- **Two-character timing.** Jess reaches for a plan card; the bloom settles on the one the user kept. If the user rejects the suggestion, Jess slides it away without a sad face. The bloom's gesture can be warm or cheeky without generating a second dialogue stream.
- **Interruptions change the scene.** “Actually, show me the article,” “Quiet,” and “Do the short version” work mid-beat and end at the source or silence immediately. A close button is not a failure state. This is where an animated character could feel responsive rather than decorative.
- **Optional visitors, with hard privacy walls.** A book-club fictional host or authored sky storyteller can appear *inside that room* for one scene, clearly distinct from real Community members. Actual user avatars or DMs never appear as animated visitors without a separate explicit design and consent review.
- **A user silhouette is a separate experiment.** In a rehearsal, a customisable figure might move an object or try a line while Jess reacts. It could increase agency, but an avatar made from photos/body data raises extra privacy and representation questions. Test an abstract, locally chosen figure before proposing likeness upload.
- **Imperfect speech is a performance choice.** An occasional pause before a difficult line, a self-correction when the user changes direction, or a laugh at a genuinely funny event can sound alive. Random coughs, chair noises and repeated “right” become a fake-human soundtrack. The silent visual performance must remain complete in its own right.

### A 50-second demonstration, as a filmable interaction

The user opens Today. No character jumps over the page. A real changed Planner item has one small “Sort this with Jess” invitation beside its existing control. Tap: the paper card folds into the atelier, Jess moves a cup out of its way, the bloom turns toward it. Jess asks, “Which bit still matters?” The user taps **Keep the call**. The other cards dim but do not vanish; **Preview changes** shows exact times and items. The user says **Quiet**; Jess stops speaking while the same controls remain. **Save plan** writes only the confirmed changes. The receipt names the changed Planner item; tapping the now-creased card reopens it. Back returns to Today at the same place. If the write fails, the card unfolds with **Try again** and **Keep old plan**, with no victory animation. If no Planner item changed, this scene never impersonates one. A second 20-second Sky scene should show delight without a task: the moon dial turns, the bloom catches light, Jess tells one brief authored and cited story, then **Read the sky** opens its real bulletin in one tap. These are storyboard examples, not already working behaviour.

### The crossing objects, not a new content silo

| Actual event/source | Object or gesture | Exact return and consent boundary |
|---|---|---|
| Saved Read paragraph | Creased ribbon/bookmark | Reopens article ID + paragraph/revision; only appears after acknowledged Save. |
| Books chapter/club checkpoint | Book with a tucked slip | Reopens exact book/position; club content remains spoiler-gated. |
| Planner item or user-confirmed move | Worn ticket/card | Reopens item ID and current state, never assumes the task happened. |
| Finished Listen choice | Record sleeve | Reopens the timed player or truthful external episode, with source failure handling. |
| Sky bulletin | Moon dial/pressed night flower | Reopens that edition and source; personal chart requires actual birth details. |
| Good life Money action | Sealed envelope | Private task/source/deadline; no payment or finance claim. |
| Community encounter | Sealed postcard | Exists only on explicit opt-in; no public sharing, DM or inferred relationship. |

Objects are *views onto existing IDs*, not a parallel shelf or pseudo-inventory. The same object can be seen in Garden, Jess and its source room; deleting/forgetting a memory should remove that presentation without deleting the underlying article or Planner item. Never create a prop for an unacknowledged write. The interaction ends with a receipt the user can understand: what changed, where it lives, and how to undo it. Existing features remain accessible even if an Ideas preview chooses a calmer first fold.

### What makes the characters feel alive without faking a person

Acting beats come from the state of the *interaction*, not random filler: Jess looks toward the object she is discussing, stops when interrupted, puts down a prop before listening, changes posture before responding, and sometimes says nothing. A scripted “hmm” on every sentence or artificial cough would sound more fake. The bloom has a different repertoire: folds, leans, sheds/collects a petal, responds to light and Jess's movement; it does not nag, display a mood score or claim emotional understanding. Humour is situational and optional: an envelope can be “the admin goblin” once, but factual advice stays exact. Preferences could include dry/warm/playful/quiet, plus a one-session “be kind today” switch; choices must be visible and reversible. The user's existing Jess name and bloom name remain independent until a demonstrated design gives a reason to change that.

This direction is an inference from the app inspection and [self-determination research](https://selfdeterminationtheory.org/SDT/documents/2006_RyanRigbyPrzybylski_MandE.pdf): choices, achievable competence and connection can create game enjoyment without points, streaks or guilt. [Generative Agents](https://research.google/pubs/generative-agents-interactive-simulacra-of-human-behavior/) links observed events, memory and planning to believable behaviour, but FemWell should remember only scoped, inspectable user-approved facts. [DialogLab's authored conversation study](https://www.research.google/blog/beyond-one-on-one-authoring-simulating-and-testing-dynamic-human-ai-group-conversations/) supports testing authored beats plus interruption/turn-taking; it does not prove our character will feel human. [Apple's motion guidance](https://developer.apple.com/design/human-interface-guidelines/motion) supports purposeful, optional movement rather than constant decoration. [ICO data protection by design/default](https://ico.org.uk/for-organisations/uk-gdpr-guidance-and-resources/accountability-and-governance/guide-to-accountability-and-governance/data-protection-by-design-and-by-default) is the UK privacy basis for explicit memory, separate display and sharing controls.

### First Ideas proof should expose the whole system

Create a compact interactive storyboard with **three art/behaviour directions** (Living Margins, Atelier, duo/theatre), then one connected slice: an actual Planner disruption or saved Read source → Jess and bloom react → user chooses/interrupts → exact action or draft → acknowledged receipt → garden object → exact source return. Include a second, lighter Sky/Listen moment so the world does not read as a productivity tool. Preserve existing Today, Garden and Jess paths in the preview; show how their repeated copy compresses visually without deleting capabilities. Test real taps/Back at 360/390/430, focus/reduced motion, signed-out and missing-source states. Measure first-load and route asset bytes, animation frame cost, first-party requests and paid AI/voice units separately. Motion is a small client state machine; no model call for a blink, pose, page view or unrequested speech. No new Base44 function name, schema or main promotion in this research phase. The Ideas desk should carry the visual clip, exact actions, what is real versus mocked, critique and a short Halli choice only after the demo can be judged.
