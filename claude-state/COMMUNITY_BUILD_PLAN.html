FemWell · Community Production Build Plan · 2026-06-09

From the approved Demo 6 to the real /Community

A detailed, sequenced implementation plan. Derived from COMMUNITY_MEGA_PLAN v2-FINAL. Approved direction = the Rooms + Tabs hybrid (Demo 6): rooms-as-doors home + tabs-inside, open-write comments with backend auto-moderation, Jess as host + active support + moderator, the whole-life rooms, Question of the Day, audio (later).

The one-line plan. Ship the editorial hybrid as the real /Community first (retire MP8), with the Lounge + comments + rooms + QOTD — comments auto-moderated server-side; then Jess games-master; then async voice-notes. Defer live audio and Phase-Twin-class infra. The build is mostly entities + a handful of Deno serverless functions + the existing editorial components from Demo 6. The two true blockers are Halli's: an OpenAI API key in Base44 secrets and the legal floor (OSA/ICO).

0 · Locked constraints (inherited; never re-litigate)

18+ adults-only · anonymous-first · UK (NHS/£/GMC) · no emoji (Lucide/SVG) · Editorial kit (Ephesis + Cormorant) · PAPER_BG · cream/plum, no espresso/gold · one bottom nav · no scoreboards / streaks / likes / counts · no paywalls on peer surfaces · Jess as warm host (never a roast) · whole-life not clinical-only · evidence-informed, never a clinical promise.

2 · Sequenced rollout (milestones)

M1 · Phase 3.5a — Route correction (ship first)

Built: retire the off-thesis MP8 forum; mount the editorial Rooms+Tabs hybrid (Demo 6, productionised) as the real /Community. Ship the Home (rooms-as-doors + ambient presence), the whole-life Rooms, Question of the Day, and the Lounge with open-write comments + reactions. Echo Wall + Witness already live — surface their doors/tabs here.

Components: productionise CommunityDemo6.jsx → a real Community.jsx (swap mock communityShared.js data for entity reads/writes; keep the exact editorial shell, palette, fonts). Reuse the door/tab nav, the Lounge comment UI, QOTD, the rooms.

Entities: CommunityPost, Comment, Reaction, QotdPrompt/QotdAnswer (repo .jsonc + sync). Functions: postCommunityPost, react, reportContent, postQotd. Comments at M1 can launch with the existing on-device keyword crisis-check; full AI auto-moderation lands in M2 with the key. (Or gate comment writing behind M2 if Halli prefers no comments without server moderation.)

Safety/legal at M1: the 18+ age-gate at the Community boundary; start the OSA paperwork (illegal-content RA, children's-access assessment — moot if 18+); the ToS proactive-tech disclosure line; explicit special-category consent in onboarding.

Data flow: client → postCommunityPost/postComment (asServiceRole) → entity → real-time sync to readers; reads via filter({hidden:false}, "-created_date").

Verification: build+lint; Playwright webkit 390×844 (home/doors, tab-switching, a post, an open + a reaction-only post, QOTD); live-walk; bundle-hash flip + marker grep; Ms Verify. Exit gate: /Community renders the editorial hybrid; MP8 retired; comments post + read.

Not done by design at M1: AI auto-moderation (M2), games-master (M3), audio (M4), Circles, Phase Twin.

M2 · Phase 3.5b — Comment auto-moderation + Jess inline support

NEEDS OPENAI KEY Built: the postComment pipeline becomes the production safety spine — every comment screened pre-publication; harmful/out-of-place ones auto-removed (tombstone), crisis routed to UK support, health-vocab allowlisted. Plus jessSupport — Jess chips in with warm support on heavy threads (the gold "Jess · here with you" cards).

Functions: postComment (OpenAI Moderation API + keyword crisis-check + allowlist + human-review queue field for borderline), jessSupport (Claude). Data flow: submit → postComment → crisis check → moderation API → write visible/removed → sync. Human-in-the-loop: borderline band → a review queue (status:flagged) + an appeals route.

Safety/legal: ToS now MUST disclose proactive moderation tech (OSA); name the human-review owner + appeals owner (Halli). Verify: submit clean/borderline/harmful/crisis comments → correct outcomes; allowlist test on anatomy/health words. Exit gate: a harmful comment is auto-removed server-side; Jess posts a support reply; clinical words are never auto-blocked.

M3 · Phase 3.6 — Jess games-master

Built: the daily gentle round — one shared prompt, a generous countdown, simultaneous reveal of the aggregate ("most of you said…"), no winner. Entities: GameRound, GameResponse. Functions: openGameRound (Claude generates the prompt; via cron or lazy open-on-first-view) + finalizeGameRound (aggregate + Claude warm reveal). Client countdown is cosmetic; the round lifecycle is server-authoritative; reveal pushed via real-time sync.

Needs: Claude integration on; a cron (else lazy open). NOT a live frame-synced multiplayer (avoided — async simultaneous-reveal sidesteps the latency/desync failure class). Verify: a round opens, answers record, close reveals the aggregate; Jess never names a winner / comments on identity. Exit gate: a daily round runs end-to-end.

M4 · Phase 4 — Async voice-notes ("a voice echo")

NEEDS STT Built: record in-browser → optional voice-mask → STT → classify → hold-before-delivery (harm never reaches the listener) → a phase-sister holds it → fades. Entity: VoiceNote. Function: postVoiceNote (MediaRecorder upload → Base44 file storage → external STT → moderation → hold/deliver). External: AssemblyAI (cheapest) or Deepgram Nova-3 (UK accents). Exit gate: a voice note is screened + held before delivery; clean notes deliver + fade.

Deferred by design (do NOT build at launch).
  • Live audio (1:1 turn-based + live Circles) — real-time AI moderation isn't safe/reliable; the only AI-native live system needs recording (breaks "no recording"). If/when built, use structural + human safety only. Needs an external WebRTC provider (LiveKit) + an OSA risk assessment.
  • Phase Twin (Q4) + the heavy pairing infra; expert AMA layer; Circles formalisation (Phase 4 if pulled forward).
  • Witness true zero-knowledge E2E (per-device keypair + key relay) — current is at-rest + access-gated; security upgrade, not launch-blocking.
