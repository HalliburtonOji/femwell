0 · The philosophy — what the Founders Corner demands

Straight from the Founders Corner, these are non-negotiable for every feature below:
  • "Health is one room, not the house." RULE 1: span life, not just health — life-stage gently tints, never dominates. Nutrition's whole-life face is food-as-joy & culture (Recipe Joy Swap, dining-out, cooking-for-friends, £ filters, a community cookbook). Macros are opt-in, never the spine.
  • No scoreboard — an ethical line, not a taste. No daily pass/fail, no calorie "budget remaining" gate, no streaks, no good/bad food colouring. This is backed by hard evidence (below) and is the thing that separates us from MyFitnessPal/ZOE.
  • Jess is a companion, never clinical. Mirror the Journal's three-role model: Prompter (gentle, stage-aware nudges), Witness (a weekly observation, not a verdict), Analyst (patterns, always labelled, always "not medical advice").
  • RULE 2: wire ALL surfaces. Every feature names a tie to Today, Journal, Community, Lifestyle, Planner, Jess, Doctor Export. Shared entities are sacred (hydration/meals logged on Today AND Nutrition hit the SAME tables).
  • 11 life stages (teen → post-menopause) reshape every screen. UK market (NHS/BDA/BNF figures, £, UK GDPR). Cream/plum, Ephesis + Cormorant, Lucide/SVG, zero emoji.

1 · The spine — one connected model (why depth needs this first)

Today the features are islands: two planners that don't talk, a shopping list that re-derives by naive text-split, MealItems written but never read, recipes that vanish, insights from 4 hardcoded if-rules. "4× per feature" only works if they share one spine:
  • One food/item model. A logged meal, a recipe ingredient, a plan slot and a shopping line are all the same normalised food row (name → canonical food → macros + micros + portion). This is what lets logging, recipes, plan and shop finally talk.
  • One plan object. Manual edits and AI generation are both edits to the same plan; the shopping list and pantry derive from it; locked slots survive regeneration.
  • One intelligence loop. Logging → targets → progress → insights → Jess, all reading the same history. Fix the orphans (read MealItems; persist recipes; surface subscores).
This spine is the real reason the current page feels thin: the data is captured then dropped. Building it is P0 and unlocks every feature.

2 · Logging — the heart of the page

Frictionless LoggingP0 P1 L
Today: a 2-row textarea + meal-type + portion buttons; every estimate round-trips the analyzeMeal LLM (slow, ~±20% error); a 28-item hardcoded FOOD_DB behind a card-deck modal; no photo, voice, or barcode UI; recents/favourites don't exist; portion is regex-parsed from a string.
a · New layoutCamera-first, search-second. The primary affordance is a big "Log" that opens a calm sheet with one row of methods — Snap · Say · Scan · Search · Recents — recents/favourites as one-tap chips right there (the single biggest speed driver in the evidence). The result of any method renders as an editable line-item list (a confirmable draft), never a locked verdict. A "no-numbers" journal mode is available for users who never want to see calories.
b · New interaction logicThe four fast paths, each one or two taps:
  • Snap — photo → AI proposes items + portions → user adjusts/removes/swaps → confirm. The correction is the training signal (SnapCalorie pattern).
  • Say / natural language — "two eggs and toast with butter" parsed into editable items (~6s/meal — the lowest-friction method).
  • Scan — barcode → exact DB match.
  • Recents / Favourites / "Repeat yesterday" — one tap to re-log; "copy yesterday's lunch."
Every result is "good-enough, one tap from edit." Lose It! measured 3.5× faster logging and 2× more foods logged from exactly this.
c · New data / AI / computation logicDB-first, LLM-as-fallback (see §3): a barcode or search hit returns deterministic macros instantly; the LLM is only the parser for free-text/voice/photo and maps its output back onto DB rows where it can. Photo uses a vision model with volumetric portion estimation, always returned as an estimate. Stop the data loss: persist the item breakdown and actually read MealItems; keep meal_score subscores instead of crunching them to one number. Learn the user's top ~30 foods to rank recents.
d · Whole-life + FemWell-fitAfter a log, surface a nutrient relevant to her stage, not a calorie tally — iron after a meal during menstruation, folate in pre-TTC/TTC, calcium+protein in peri/menopause. Optional "how did it feel?" (satisfied / rushed / with people) — qualitative, never scored. Calories opt-in; no good/bad colour. This is the harm-evidence response, made warm.
e · Build size + gated depsL overall, but shippable in slices. Vision model cost (photo), food-DB API (scan/search), voice via Web Speech API (no third-party — matches Sprint 7). Recents/favourites + natural-language reuse what exists = M and first.
f · PriorityP0 recents/favourites + the editable-draft pattern + read MealItems. P1 photo + voice + barcode.
Evidence: Lose It! Snap It (TechCrunch); SnapCalorie + Nutrition5k (CVPR 2021), independent ±19.8% MAPE; Passio voice ~6s/meal; WW Food Scanner editable-list. Harm: Levinson et al. (Int. J. Eating Disorders) ~75% of an ED sample used MFP, 73% felt it contributed; Flinders review of 38 studies; balanced by a low-risk-user RCT (PubMed 34427188) — so: opt-in numbers, no scoreboard, no shame.

3 · The food database — the deterministic floor

Real Food DatabaseP0 L API + attribution
Today: a 28-item hardcoded array. Everything else round-trips the LLM. No barcode, no UK foods, no micronutrients, no personal history.
a · LayoutInvisible by design — it powers Search/Scan/Recents (§2). A clean result row: food name, brand if any, portion picker (sensible UK units, not regex), macro + key-micro chips, "add."
b/c · Logic & architecture (the important part)Three layers:
  1. UK CoFID lab floor (McCance & Widdowson, ~3,300 UK generic foods, Crown-open, free) — the trusted generic-food base, and it already carries iron, folate, calcium per food, so the women's-nutrition layer (§11) comes for free.
  2. Barcode → Open Food Facts (2.5M+ products, UK-strong, free, barcode-native) for packaged foods.
  3. LLM parser only on a miss, mapped back onto DB rows; free-form text only as last resort, always editable.
Cache hot lookups from Open Food Facts' nightly bulk dumps so we don't hammer the API. This is the architecture that gives Cronometer its accuracy edge (lab-sourced) over MyFitnessPal (crowdsourced, ~37% of entries >20% energy error).
d · Whole-life + fitUK-first foods (CoFID) make it feel local and trustworthy; micronutrient fields enable stage-aware surfacing without a paid add-on.
e · GatedOpen Food Facts = ODbL attribution + share-alike; images CC-BY-SA — must credit. CoFID is Crown-open (safest, no fee). Caching/rate-limit eng. L.
f · PriorityP0 — the floor under logging, recipes, plan and insights. Build CoFID + a barcode source first; LLM stays as the parser.
Open Food Facts data/licensing; gov.uk CoFID; FatSecret/Nutritionix (paid barcode alts); Macronutrient-calculator Cronometer 30/30 vs MFP 11/30 (indicative).

4 · Targets & the gentle engine

Targets / Macro EngineP0 S
Today: calorie target is a hardcoded 2000 default (with a dual-key bug calories_target vs calorie_target); macro targets are flat constants; "goal mode" is a label that changes nothing; phase-awareness is cosmetic tips.
a · LayoutNot a goal screen. A quiet, derived default that lives behind the day-glance; editable, framed as "a gentle guide, not a cap."
b/c · LogicDerive a real estimate from body metrics + activity + life stage (a transparent TDEE-style formula, no external API), expressed as a range (e.g. 1800–2200) not a single number. Stage tilts it: +protein and calcium/vit-D weighting in peri/menopause; folate emphasis pre-conception; gentle iron focus during menstruation. Fix the dual-key + the legacy-shape calorie bug so history reads correctly.
d · FitTargets are opt-in and de-emphasised — the no-scoreboard line. They tune nudges underneath; they never gate the day.
e · GatedFormula only — none. Light medical-claims pass on stage copy. S.
f · PriorityP0 — without real targets, every macro/progress number is arbitrary.

5 · Hydration & drinks

Hydration & DrinksP1 P2 S
Today: works, but it's a separate chore — progress bar + glass dots + +250/500/750 buttons; drink calories are blanket hardcoded constants; flat 2000ml target.
a · LayoutGlance, not chore. One fill-level ring folded into the daily snapshot (WaterMinder/Waterllama pattern), one-tap preset cups, a warm recap rather than a deficit tally.
b/c · LogicPersonalised goal from weight + activity + life stage (higher in pregnancy T1–T3 and breastfeeding/postpartum, per BNF/NHS), not flat 2L. Count all fluids (NHS Eatwell: 6–8 glasses of fluids incl. teas/milk) — don't penalise non-water; gentle note on caffeine/alcohol rather than fake "dehydration maths." Schedule-aware reminders.
d · FitFramed as care/energy ("a glass for you"), tied to the joy framing — never a quota to fail.
e/fNone gated. S. P1 fold-into-snapshot + stage goal; P2 reminders/recap.
WaterMinder; Waterllama; Hydro Coach (weight/activity/weather goal); BNF "Hydration and pregnancy"; NHS Eatwell.

6 · The unified planner (manual + AI = one model)

Meal PlanningP0 P1 M
Today: two disconnected planners — "My Plan" (manual, 4 hardcoded suggestion strings per slot, no macros, dumb text-split shopping) and "AI Plan" (generates, but save overwrites the whole week and clobbers manual work). No locking, no pantry awareness.
a · LayoutOne week grid (days × slots), each cell a tappable recipe/meal card, a persistent preference rail, a single "regenerate." "Doable in real life," not a maximal grid (Mealime).
b/c · LogicManual and AI are edits to the SAME plan object. AI proposes; the user drags/swaps/locks cells; locked cells survive regeneration. Per-cell swap and per-day regenerate (Eat This Much / Mealime granularity). Allergies = hard constraints; budget + preferences + stage = soft weights. Pantry-aware generation (uses what you already own). A live macro/nutrient preview so you see the week before committing.
d · FitStage-aware as a soft nudge (gently weight iron-rich meals when menstruating; calcium/protein peri/menopause) — never a calorie engine. Lead with "an enjoyable, doable week," £-filter available.
e/fNone gated (reuses the generate fn). M. P0 unify into one model (kills the duplicate mental model); P1 lock/swap/pantry-aware + macro preview.
Mealime (doable weeks, per-meal swap); Eat This Much (target-driven, lock/regenerate); PlateJoy (preference + pantry-aware; service discontinued Jul 2025 — historical).

7 · Recipes & cook-from-what-you-have

RecipesP1 P2 M
Today: two recipe generators (one a stale orphan, AIRecipeGenerator); recipes aren't persisted (lost unless copy-pasted); no scaling, no photo, no ratings, no history, ingredients not cross-referenced with plan/shop.
a · LayoutA single scrollable recipe object: hero block → time/servings/difficulty chips → ingredient list (toggleable against your pantry) → per-step "guided mode" cards with timers (SideChef pattern). One saved library, ratings, collections.
b/c · LogicPhoto-to-recipe: snap the fridge → AI returns a recipe + a shopping list for only the missing items. Non-destructive single-ingredient swaps ("swap this, keep the flavour/nutrient profile"). Persist recipes as a real entity (ingredients + steps + nutrition), scale to servings, rate, and feed ratings into future suggestions. Ingredients are the shared food model, so they cross-reference plan + shop automatically.
d · Fit — the differentiatorThis is the whole-life face: cooking confidence as the outcome, not weight. "You tried something new" moments; cultural/world-cuisine celebration; cook-for-friends; a community cookbook hook. The cooking-RCT evidence supports joy & confidence claims (do NOT claim "cooking improves your diet" — it didn't move intake in the trial).
e/fVision model for photo-to-recipe. Persistence/scaling = M. P1 persist + scale + save/rate + swaps; P2 photo-to-recipe + guided mode.
SideChef AI (guided steps, RecipeGen, MySubstitution); Samsung Food (import/normalise/collections, Vision AI); cooking-confidence RCT Begley et al. (PMC8970183) — confidence/wellbeing up, diet unchanged.

8 · Shopping & pantry

Shopping & PantryP1 P2 M
Today: list groups by category but is built by a naive text-split + an LLM categorise call ("Chicken + sweet potato & greens" → 3 items); sync is destructive; quantities are rough guesses; no pantry; "sorted by aisle" is copy, not built.
a · LayoutAuto-generated list grouped by aisle so the store path is linear; manual vs plan-sourced items distinguished; a pantry view.
b/c · LogicBuilt from the shared plan/food model (no text-splitting): ingredient normalise → unit-aware merge (Monday's + Tuesday's onions → "2 onions") → set-subtract the pantry (what you already own, added by type or camera-scan) → aisle classify. Re-syncs non-destructively when the plan changes.
d · FitBudget mode: cheaper-swap suggestions framed as money-saving (not calorie-cutting), tied to UK budget-cooking guidance — inclusive, whole-life, opt-in.
e/fNone gated (heuristics). M. P1 auto-build + merge + aisle from the shared model; P2 pantry set-subtract + budget swaps.
Fond (auto-build, merge, pantry set-subtract); Samsung Food pantry/Food-List; Meal2Shop (aisle order, price compare).

9 · Progress — patterns, not scores

Progress / MetricsP1 M
Today: body metrics are stored but never visualised; "progress" is a 7-day calorie line + hydration bar; the legacy-shape bug makes recent meals read 0; phase colour is cosmetic; goal mode does nothing.
a · LayoutA single gentle composite ("how nourished has the week felt") in the spirit of Lifesum's Life Score — positive reinforcement, not a calorie verdict — plus correlation cards: food↔mood, food↔energy.
b/c · LogicCompute correlations over time from the shared history + DailyCheckins (energy/mood/digestion) — "your brightest-energy days line up with iron-rich meals." Show trends, not streaks. Cycle as an observed-pattern lens for her own data (legitimate), never a prescription. Visualise the body metrics that exist; let weight be optional and never the headline.
d · Fit — what we NEVER showNo calorie pass/fail, no weight-as-headline, no streaks that punish a missed day, no "you failed." Progress-not-perfection. This is the intuitive-eating evidence in UI form.
e/fDepends on the P0 bug fix + the spine. M. P1.
Lifesum Life Score (Scientific Reports 2025 — self-monitoring → mindfulness); Intuitive Eating evidence (Tribole & Resch; PubMed 28619668).

11 · Women's nutrition intelligence (cross-cutting)

The stage-aware micronutrient layerP1 medical-claims M
Today: cycle-awareness lives in a few hardcoded tips; no real per-stage nutrient intelligence; nothing uses the food DB's micros (because there is no real DB yet).
The intelligence (grounded in UK evidence — gentle nudges, NEVER scoreboards):
NutrientUK figureStage relevance
IronRNI 14.8 mg/day (19–50) vs 8.7 at 50+Menstruating / teen — the single most solid cycle angle
Folate / folic acid200µg base; 400µg pre-conception→wk12pre-TTC, TTC, pregnant-T1

EVIDENCE GUARDRAILS — honesty as a feature
  • Strong / ship it: iron (menstruation), folate (pre-conception), calcium+vit-D+protein (peri/menopause) — established BDA/NHS guidance, as gentle nudges.
  • Weak — do NOT prescribe: cycle-syncing macros. A systematic review found "lack of consistency to confidently advise" and no macro↔symptom correlation; an expert panel "unanimously agreed the evidence isn't there." Frame as self-awareness only.
  • Weak — do NOT overclaim: microbiome / ZOE-style personalisation. Which? was "not convinced it offered truly personalised advice"; ZOE dropped its CGM in 2025. Generic-but-true nudges beat fake precision — and that honesty is a UK-market trust differentiator.
PriorityP1, riding on the food DB (§3) + insights (§10). Medical-claims copy review before ship.
BDA Food Fact Sheets (menopause, fibre, calcium); BNF women's nutrition; NHS DRVs; Cambridge Core systematic review (cycle-syncing); Which? ZOE review. Verify exact RNIs against SACN/BNF before shipping copy.

12 · The whole-life & joy layer (the thing no competitor has)

Food as joy & cultureP2 FUT M
Today: essentially absent — the module is macro-first with a wellness veneer; joy/culture/social isn't first-class UI. Yet the Founders Corner names this as nutrition's whole-life face.
The layer (Founders-Corner aligned)
  • "How did it feel" log — satisfied / rushed / with people — a non-macro reflection that can flow into a Journal prompt.
  • Recipe Joy Swap, dining-out mode, cook-for-friends, cultural/world-cuisine celebration.
  • Budget (£) filters and batch-cook — inclusive, food-security-aware.
  • Community cookbook — share a recipe or a small win anonymously; the cook-together future hook (+232% joy when cooking together — Gallup).
This is the differentiator: Flo/Clue have women + community but no nutrition; MFP/ZOE have tracking + diet-culture baggage. No one owns food-as-joy for women across 11 life stages.
PriorityP2 for the solo joy bits (how-it-felt, joy swap, £ filters); FUT for social cook-together (gated on Community maturity + moderation + legal).
WholeLifeDoc ("food-as-joy & culture… macros opt-in"); Gallup cooking-joy; cooking-confidence↔wellbeing (Frontiers).

13 · Jess as nutrition companion (cross-cutting)

Not a separate chatbot — the same Jess, three roles (mirroring the Journal):
  • Prompter — gentle, opt-in, stage-aware nudges ("a little iron at dinner would round today out"); never nags, never scores.
  • Witness — a warm weekly observation from how you ate, not interpreted into a verdict.
  • Analyst — the weekly story + pattern surfacing (§10), always labelled, always "not medical advice," never clinical (MHRA risk if she sounds diagnostic).
"Ask Jess about food" / "what could I make with this" reuses the fw_open_assistant connectivity event — voice continuity, not a new surface. Any new nutrition entity MUST be exposed to Jess's context (critical data rule).

16 · Gated dependencies & compliance (the Halli calls)

  • Food DB — Open Food Facts (free, ODbL attribution + share-alike, CC-BY-SA images) + UK CoFID (Crown-open). Caching infra. Decision: approve the DB architecture + attribution.
  • Vision model (photo logging + photo-to-recipe) — cost per call. Decision: approve a vision model + budget.
  • Voice — Web Speech API (no third-party, matches Sprint 7) — no gate.
  • Medical-claims pass — any micronutrient / stage / cycle copy gets a light legal/claims review before ship (MHRA: Jess must never read clinical).
  • Honesty guardrails — cycle-syncing macros + microbiome personalisation stay flagged/optional, never the spine (the evidence doesn't support selling them as truth; saying so is a trust differentiator).
Headline. Build the spine first so the data stops being dropped; put a real UK food database under everything; make logging frictionless and kind (snap/say/scan/recents, editable drafts, no scoreboard); then reimagine each feature on top — a unified planner, a real recipe library with joy at its centre, smart shopping, pattern-not-score progress, a Jess weekly story, and a gentle stage-aware micronutrient layer grounded in BDA/NHS. Lead with the thing no competitor has: food as joy & culture for women across 11 life stages, macros opt-in. That is the nutrition feature "no competitor can copy."
