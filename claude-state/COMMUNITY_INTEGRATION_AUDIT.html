FemWell · Community · Cross-surface integration audit

How well is Community connected?

Maps how the live /Community actually connects to every other surface vs. the intended connections in COMMUNITY_MEGA_PLAN §6. Evidence-based (file:line, 4-agent code sweep). Each gap tagged by severity + BUILD (clear fix) vs DECISION (needs Halli). Dated 2026-06-11.

Headline: the bones are wired — Community is reachable, the rooms/QOTD/Clubs/Book-Club work, and the Doctor's Export privacy contract holds (no peer-content leak). But Community is siloed from the peer features the mega-plan calls its spine: the Echo Wall is displayed nowhere live (echoes are written but never readable), and Witness, Phase Twin, Today, and the Jess assistant have no entry points to/from Community. Five clear build-wins + a short decision list below.

The one that matters most — the Echo Wall is dark

CRITICAL BUILD   The Echo Wall is mounted nowhere in the live app.

The Journal can write an echo (FourLivesChooser → ShareAsEchoSheet → postEcho, wired). But the wall that displays echoes — the built src/components/journal/echo/EchoWall.jsx — is rendered only inside CommunityDemo3.jsx (a FoundersOS demo). No live page calls Echo.filter. So a woman can share a line into the void, and no one — not even she — can ever read the wall. The core "share-as-echo → wall" loop is broken; it was dropped when Community was rebuilt as Demo 6.

Fix (clear): mount the existing EchoWall.jsx on Community as its own surface (a home card + view, or an "Echo Wall" entry). The component is self-contained (its own load/empty/error states, reactions, retract). This restores the flagship anonymous wall with no new backend.
