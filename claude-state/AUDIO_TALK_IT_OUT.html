Audio / Talk-It-Out

Being heard out loud — anonymously, safely, without anyone fixing you. Three modes, one warm room. 18+, anonymity-first, no recordings, no scoreboards.

The idea. Sometimes a woman doesn't want to type — she wants to say it out loud and be heard. Talk-It-Out gives three ways: (A) async voice-notes (whisper a line, a phase-sister holds it), (B) 1:1 turn-based "talk it out" (3-min talk / listen / swap, "hold, don't fix"), and (C) small live Circles (5–8, status-flattened, Jess-seeded). It is the spoken sibling of the Echo Wall (anonymous one-liners) and Witness (one entry, one holder).
Headline feasibility verdict. Mode A (async voice-notes) is buildable in-repo today — record in-browser (MediaRecorder) → Base44 file upload → a VoiceNote entity, reusing the Echo anonymity/fade/crisis scaffolding. Modes B & C (live audio) are NOT possible on Base44 alone — live media must route through an external WebRTC provider (recommend LiveKit); Base44 can host the token function, but Halli must create a provider account + keys, create the entity, and commission an OSA risk assessment first. Ship async-first; live later.

1 · Why audio, and the two hard truths

Being heard (not advised) helps. 7 Cups trains every listener and forbids advice; the Samaritans model is "listening is active… reflect back without adding our own suggestions." A turn-based "talking-stick" timer operationalises exactly this — one speaks, the other holds. [HIGH] [HIGH]

Hard truth 1 — co-rumination. Venting isn't automatically good: two people rehashing distress without resolution worsens depression/anxiety, and distress is contagious between friends. Design requirement: a turn timer + a gentle closing reflection ("what would help right now?") to steer toward expressive disclosure (narrate → make meaning → move on), not a doom-loop. [HIGH]

Hard truth 2 — live-only kills products. Clubhouse went 0→10M then lost ~93% of engagement; liveness is high-friction. Async is the healthy core; live is an occasional layer. [HIGH]

2 · Mode A — Async voice-notes (ship first)

The lowest-pressure, healthiest, simplest. The "voice Echo."

UX flow

Record a short voice note (cap ~60s) → optional voice-mask (pitch/formant) → on-device STT crisis-scan (the existing text lexicon) + cooling hold (reuse echoSafety) → deliver to a phase/interest-matched sister's "held for you" inbox → it fades (48h, like an echo). The holder can send back one fixed spoken/text response (the Witness 4 lines) or hold in silence — never a back-and-forth thread.

Matching

Same as Echo/Witness: phase + life-stage + interest, never self; pull-based claim from a held queue.

Anonymity

Device-derived hash (separate namespace, like witnessHash). Optional voice masking (pitch/formant shift). Honest limit: masking makes a voice harder to recognise, not anonymous — voiceprints can survive naive modulation (V-Cloak/VoicePM research). Frame as "harder to recognise," pair with no-PII.

Safety

Async's big advantage: you can scan/hold the recording BEFORE delivery — STT → text crisis lexicon → if tripped, route to support, never deliver. No recording stored long-term beyond the fade; report→hide (Echo pattern).

Data model

New entity VoiceNote (audio_url, author_hash, phase, life_stage, masked, live_at, expires_at, held_by_hash, response_code, hidden, report_count) — directly parallels Echo.

Infra

In-browser MediaRecorder → Base44 UploadFile (CDN URL → entity field) → entity row. No realtime provider. verify confirm Base44 UploadFile accepts audio MIME in a 10-min spike (documented for image/PDF; audio is on the feature board).

3 · Mode B — 1:1 turn-based "Talk It Out"

The talking-stick vent. Live, but structured so it can't become advice-giving or cross-talk.

UX flow

Charter (shown once: anonymous · no recording · "hold, don't fix" · 18+ · leave/mute/block/report any time) → match a phase/interest sister → connect (voice only, optional mask) → turn 1: you talk 3 min, she holds (her mic auto-muted, a "holding with you" indicator) → swap: she talks 3 min, you hold → optional second round → closing reflection ("one thing that would help this week") → seal (nothing stored). A visible timer runs each turn; either can leave / mute / block / report at any moment; a panic-exit ends instantly.

Matching / pairing

Like Witness — pull-based, phase + life-stage + language + (optionally) the vent topic (a Lounge/Circle tag); never self-match.

Timers

3-min talk / 3-min listen / swap (tunable). The timer is the "talking stick" — it enforces being-heard and prevents the co-rumination doom-loop.

Anonymity

Hash identity; no names; optional voice mask (same honest limit as Mode A). No recording — ever.

Safety / moderation (audio is harder)

  • No keyword scan in live audio (you can't regex a live stream). So crisis safety is human + structural: an always-visible signpost card (Samaritans 116 123 · NHS 111 · Shout 85258 · Mind), a one-tap panic-exit, and a "this needs more than us" escalation that ends the turn and surfaces resources.
  • Report → instant leave + block (never make the victim moderate in real time — Clubhouse's mistake).
  • No recording by default (privacy + ephemerality), stated visibly.
  • Closing reflection nudges toward resolution (anti-co-rumination).

Data model

TalkSession (a_hash, b_hash, topic, started_at, ended_at, ended_reason) + TalkStrike (reuse the Witness strike pattern for repeat reporters). No audio stored. A LiveKit room name + tokens are ephemeral, never persisted.

Infra

Needs a realtime provider (LiveKit) + a Base44 token function. See §5.

4 · Mode C — Small live audio Circles (last)

5–8 women, a gentle topic, Jess-seeded. The whole-life voice room — book chat, career vent, "spill it" night — not clinical-only.

UX flow

Scheduled or ad-hoc room with a topic (from a Circle — dating, career, a book, a vent) → status-flattened (Peanut Pods model: no stage/podium, everyone equal) → audience muted by default, request-to-speak (hand-raise) so no one talks over → a host present (a trained member or Jess-seeded prompts) → listen-only is allowed (lurking is full membership) → ephemeral, no recording → ends.

Why status-flattened

Peanut deliberately removed Clubhouse's "stage" to give everyone equal status whether speaking or not — the right fit for anonymity-first / no-scoreboard. [HIGH]

Safety

Muted-by-default audience + request-to-speak + host + always-on signpost + panic-exit + report→remove. Highest moderation/legal burden of the three → ships last.

Data model

AudioRoom (topic, circle_id, host_hash, started_at, max_size, status) + ephemeral participant tokens. No audio stored.

5 · Realtime infrastructure — the critical dependency

Every live mode (B, C) uses the same architecture: React client ⇄ WebRTC media via an external SFU provider, with a backend token function holding the API secret. Provider comparison (all WebRTC SFUs):

6 · UK legal note (audio)

The Online Safety Act 2023 contemplates voice and text chat in user-to-user services. A "one-to-one live aural communication" may be exempt — but only if truly peer-to-peer; routing voice through a provider SFU (which we will) likely brings it in scope. So do not assume the 1:1 exemption applies — a written illegal-content risk assessment is the safe default before live audio carries real traffic (Halli/legal, consistent with the Community 18+ / named-accountable-person decisions). [HIGH]

7 · How it ties to Echo / Witness / Circles

  • Echo Wall ↔ Mode A: a voice-note is "an echo you can hear" — same anonymity, fade, crisis, hold-don't-reply ethos; an Echo line can offer "say this out loud instead."
  • Witness ↔ Mode B: Talk-It-Out is Witness in voice — one held entry becomes one held conversation; the 4 fixed responses + "pass in silence" carry over; the held-3 gate could apply.
  • Circles ↔ Mode C: a live audio room is a Circle's voice session — dating/career/book/vent topics, not clinical-only.
  • Lounge ↔ all: a Lounge vent can escalate to "talk it out with one sister" or "join tonight's voice room."
  • Jess: hosts/seeds room prompts, scaffolds the closing reflection, never records or advises clinically.

8 · End-to-end + build verdict

How it actually works (async-first): a woman taps "say it out loud" → records 40s about a rubbish day → optional mask → her phone transcribes + scans for crisis + holds it 10 min → it lands in a phase-sister's "held for you" → the sister listens once, taps "holding with you" → both fade in 48h. No thread, no names, no recording kept. This is fully buildable in-repo (pending the audio-MIME spike + the VoiceNote entity sync).

Live (B/C) is a Phase-later build gated on: Halli creating a LiveKit account + keys, the entities, and an OSA risk assessment. The code (token function + client SDK join) is small and self-contained once those exist.

Recommended phasing: A (async voice-notes) → B (1:1 talk-it-out) → C (live Circles).
