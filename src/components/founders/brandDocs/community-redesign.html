One clear house, not eleven doors

Community is feature-rich and safe — but it grew a tangle of parallel words (rooms, circles, clubs, corners, the wall, the pool) and four different maps of the same places. You said it feels disorganised — it is, and this doc proves exactly where and why, then lays out a clearer structure on the canonical page language (flora hero, sliding rows, clipboard shelves, the one Jump map). No live Community code changed — this is the plan for your reaction.

The one-line thesis

The problem isn't the features — it's that Community uses three grouping words with fuzzy edges (Rooms / Circles / Clubs) and shows the same destinations four different ways (a door grid, a daily-rotating slot, a sticky tab strip, and the Jump sheet), each a different subset with different labels. The fix: one hierarchy, four clearly-named shelves, shown by ONE map — laid onto the Nutrition-style page (flora hero → summary → sliding rows → clipboard shelves → handy row). Every feature is kept — reorganised, never stripped.

2 · Diagnosis

Why it feels disorganised — 7 named faults

Fault 1Three grouping words, fuzzy edges

"Rooms" vs "Circles" vs "Clubs" — a user can't predict which word holds what. And they overlap: Circles is itself a Room; books/reading lives in FOUR places (a Books circle · the Library room · the Book Club · per-book readers'-corner clubs) and creativity in TWO (a Creativity circle · a Creativity-corner club).

Fault 2Doors don't behave the same

One affordance (a tile in the grid) does four different jobs — open a feed, open a directory of more doors, open a game, or leave for the Journal. Nothing signals which.

Fault 3Four rival navigators

The door grid, the daily slot, the sticky tabs and the Jump sheet each show a different slice with different names. No map to learn — you re-orient every screen.

Fault 4The daily slot hides 3 of 4 features

Wisdom, Pool, Close-the-week and Clubs each surface only ~1 day in 4 through that single rotating slot — otherwise they're near-unreachable. Discoverability is a lottery.

Fault 5Split-brain with the Journal

Echo Wall, Witness and Phase Twin are advertised in Community but actually live in / route to the Journal. The boundary is invisible — you tap a "Community" thing and land somewhere else.

Fault 6No canonical page structure

No flora hero, no summary card, no sliding rows, no card language — it's a bespoke scroll with its own nav stack and a different back-button label per branch ("Community" / "Circles" / "Clubs" / "Doors").

Fault 7Poetic names, no signposts

Lounge, Circles, Clubs, Living Wisdom, Close the Week, Together This Week, Readers' Corner — lovely, but nothing tells a user what's a place vs what's a daily ritual. The vocabulary is the load.

Root cause in one line: the app has ~25 real surfaces and only enough structure to keep them next to each other, not under each other. It needs one shallow hierarchy and one map.

3 · The template

The canonical page structure we build onto

The brand's page language (bible §6.8 / the Nutrition page as the reference) is exactly the discipline Community lacks. Every primary page opens the same signature top, then varies below:

  • Flora hero (FwFloraHero) — the animated realistic bough; tap-to-rebloom controller cards under it re-title the hero and re-bloom the same flower. Here the controllers become the section switcher.
  • ONE Summary card — a signal-driven "what's alive here today," never hollow.
  • Top-area chrome (§6.8.1) — the Jump-to pill + up to two page actions, same spot every page.
  • Uniform top sliding row — equal-height cards; a swipeable "today" deck + a Jess digest card with an upward inner sheet.
  • Clipboard shelves (§6.10) — a big framed board holding a tidy tile-grid; slide sideways to the next board. This is the exact tool for "several peer rooms/areas."
  • Compact one-line "handy right now" row · uniform same-row cards · no dead space.

Community's mess maps perfectly: the parallel nouns become peer clipboard boards; the four rival navigators collapse into the hero switcher = the boards = the Jump map (one map, three touch-points).

4 · The core idea

One hierarchy. Four clearly-named shelves.

Collapse "Rooms / Circles / Clubs / corners / wall" into FOUR shelves a user can learn in one glance. Every one of today's surfaces lands in exactly one shelf — no surface in two places, no door that behaves unlike its neighbours.

8 · Sequencing

What I'd build first — and what I need from you

Phased, demo-first (live Community untouched until you approve)

  • Phase 1 — the new home shell (a demo route). Flora hero + switcher · summary card · the Today sliding deck · the 4-board clipboard slider · handy row · the one Jump sheet. Wired to the real data + real rooms behind it, so it's tappable. Live pages untouched.
  • Phase 2 — consolidate the duplicates. Fold the Books circle → Library; the Creativity circle → Creativity corner; retire the daily-rotating slot in favour of the deck. Unify the back-nav to the signature top + Jump on every layer.
  • Phase 3 — promote to live /Community (one-file shell swap, revert-safe, same pattern as the Nutrition V2 promotion), then Ms Verify live-walk at 390px.

Open questions for you (Halli)

  • The four shelf names — happy with Talk · Circles · Together · Quietly? Or prefer e.g. "Rooms" for shelf 1, "Circles/Cohorts," "Do together," "Just you"?
