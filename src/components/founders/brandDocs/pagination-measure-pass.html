Motherboard component #4 · 16 Jul 2026

The measure

A 2,000-line pagination engine was measuring its pages in a column 24% wider than the one it draws them in.

What was mis-measuring

The mirror was the wrong width.

The reader paginates by laying every paragraph out in a hidden measuring layer and asking how tall they are. That layer was capped at max-width: 720px — while the real reading column is 580px (480/680 on the narrow/wide margin settings).

Width is the determinant of measured text height. Measuring in a column ~24% too wide means every paragraph is reported shorter than it renders → the slicer packs too many onto a page → the last one overflows a hard-clipped body. That is precisely the "cut off last line". It has been silently losing the bottom of pages, and it would have got worse the moment the type changed.

Four more, all real

DefectWhy it broke
The 1.5× type.ds-reader-p used 'Fraunces' — which index.css remaps at size-adjust:150%. The 18px default really rendered at ~27px → ~29 CPL; XL at ~34.5px → ~22 CPL. The reader read enormous, and the 580px column was designed for the un-adjusted face.

The research corrected my plan three times honest

I was going to build the wrong thing.

  • "Build a proper measuring mirror" — no. The 29-property mirror list everyone copies comes from a textarea library and is incomplete for prose (no hyphens, fontKerning, whiteSpace, overflowWrap). Every property you forget is a silent mispagination — and an app-wide type change is exactly the event that desynchronises a hand-copied list. Measure the real, already-styled container, hidden with visibility:hidden (never display:none — it generates no boxes, so there'd be nothing to measure).
  • The clean-break formula I'd have reached for is unsourced and wrong. floor(available / lineHeight) × lineHeight has no authority behind it, assumes uniform leading, and breaks at any heading, blockquote or image. The correct cut is the last line-box whose bottom fits — sub-pixel, via rects.
  • Orphans/widows CSS wouldn't have helped. orphans/widows don't work in non-fragmented flow; break-inside:avoid only binds when the browser fragments — and we are our own fragmenter. Both would have been inert.
  • And no library. Every live option is an EPUB or print engine (epub.js needs EPUB files; paged.js targets PDF; bindery is dead). Our in-house approach is right.
  • One thing needed no work: size-adjust requires no special handling — measuring in the same declared font accounts for it automatically. The remap was a type bug, not a measurement one.
The fix

Measure what you actually draw.

  • The mirror now inherits the real column width — its max-width:720px is gone, so it measures the page it renders. This is the cut-line fix.
  • Un-adjusted serif + a re-baselined scale, both read from the ONE standard (READING.fontStack, READING.scale) so it can't drift from the other readers again. Default 18px means 18px → ~38 CPL at 390px, the honest mobile accept.
  • The magic number is gone. Available height is now measured: from where the real body starts to where the stage's content box ends. Nothing to re-tune when the chrome or type changes.
  • document.fonts.ready gate — paint once, then re-measure the moment the real fonts land.
  • getBoundingClientRect() everywhere — sub-pixel; no 1px admit/drop.
  • Font / line-spacing / margins now re-paginate (a layoutKey in the dependencies).
  • Resume is a paragraph ANCHOR, not a page. We save the paragraph she was on and resolve the page after the measurement — so she lands exactly where she left off no matter how the text reflowed. Old saved positions still work (legacy fallback), so nobody loses their place on this deploy.
  • No more silent clipping. A single paragraph taller than the screen can't be split by a between-paragraphs engine — it used to be cut off. That rare page now scrolls. A scroll is a nuisance; missing words are a bug.

Orphans/widows: impossible by construction here — the engine only ever breaks between paragraphs, never inside one.

Deliberately not done

Two things I left alone, on purpose.

  • Mid-paragraph breaking (binary-search + Range.getClientRects()) — the full engine upgrade. It would let a page fill to the last line and kill the over-tall case properly. It's a rewrite of the slicer, not a measure pass; noted as the upgrade path.
  • Deleting src/pages/Lifestyle.jsx — I did not delete it, and I think the brief was working from my own imprecise wording. No route maps to it, but pages.config.js still imports it and the line beneath the route says: "ONE-LINE REVERT: change the line above back to "Lifestyle": Lifestyle". It's the deliberate revert path — the same convention we keep for Profile.jsx and Today.jsx. Deleting it removes the escape hatch and breaks the build unless the import goes too. Say the word and I'll remove file + import + comment together.
Also fixed — a control that lied

"Sans" was a serif.

The reader offers a Serif / Sans choice. But index.css remaps both 'Fraunces' and 'Inter' to Cormorant — so picking "Sans" gave you Cormorant, a serif, at 150%. The toggle did nothing but pretend. "Sans" now resolves to a real system sans, and both options measure correctly.
