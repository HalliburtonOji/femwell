FemWell · Community · THE SUBSTANCE PLAN · every feature · vision + build order

From working to worth returning to

The shelves are built and safe — but thin. This is the plan to give every Community feature real substance: actual content and mechanics, proper explanation, conversation and engagement drivers, and reasons a woman comes back. One doc, all eight features, an honest backend split, and a recommended order. Games is done (the model); the rest follow the same bar.

The substance test (applied to every feature)

A feature has substance when it passes five checks:

  • Real content/mechanics — something genuinely worth doing, not a thin container.
  • Explanation/onboarding — a woman instantly understands what it is and how to use it.
  • Drivers — prompts, starters, hosts that get her participating.
  • Return nudges — a concrete reason to come back tomorrow ("someone replied", "today's word is up").
  • Why she returns — the emotional payoff (belonging, being heard, a little joy, being believed).

1 · Talk rooms

Real warm conversation

Thin now: a flat feed, a one-line daily prompt, flat comments (no reply-to-reply), no first-post welcome, and few reasons to return once you've posted.

Depth ideas

  • Threaded replies — reply-to-reply so a real conversation can build (today it's flat).
  • The daily prompt as a proper ritual — a warm setup + the question + a one-tap answer, per room (Lounge/Love/Money/Style/Health/Lighter), life-stage-tinted.
  • Warm first-post welcome — a guaranteed kind reply to a woman's first-ever post (the biggest retention lever).
  • Weekly rituals — "Weekly Wins" (Fri) and "Weekly Vent" (Mon) recurring threads per room.
  • Trending this week — a k-anon "the Lounge is talking about work stress" beat (no counts).
  • Voice notes (built, gated on an STT key).
Nudges: "someone replied to your vent" · "today's Lounge question is up" · "your line got three kind hearts".

now: rich prompts · first-post welcome · weekly threads (client + Jess) threaded replies = Comment.parent_id field reply notifications = a notify path

2 · Together (the hub)

A room that's actually doing something

Thin now: the "this week, together" moment is a static rotation; the pillars are just links; the only real shared thing is the kindness pool.

Depth ideas

  • A real weekly challenge with shared progress — "the room read 40 chapters this week", "37 joined the wind-down" — aggregate, never a rank; streak-freeze so a missed day never shames.
  • Watch-along — a real schedule ("Friday comfort film") + a persistent per-episode reaction thread.
  • Co-working / body-doubling — a fixed-slot room (declare intention, cameras optional) — the proven belonging format.
  • An aggregate "what the room is doing" front door so it never reads empty.
Nudges: "this week's challenge is live" · "the wind-down starts at 8" · "the room's halfway to its goal".

now: richer rotating moment · real kindness-pool challenges full challenges/watch-along = a TogetherActivity entity + light fn live co-working = real-time/audio

3 · Events

Go together, safely

Thin now: the list depends on EventsItems being populated (often sparse); going-status is private but there's no "who's going" / pods; no reminders; discovery is a plain list.

Depth ideas

  • A real, populated feed — curated + refreshEvents; categories, "near you" at venue/town level (never precise), women-only vs mixed tags, accessibility.
  • Go-together pods — opt-in, pseudonymous, in-app-only, "meet at the door" (the EventPod entity is already added).
  • "Get home safe" check-in — expected-return time, one-tap "I'm safe", optional trusted-contact share.
  • Reminders + post-event reconnection — "your walk's tomorrow"; "lovely having you — find the next one?".
Nudges: "your event is tomorrow at 10" · "two women are going too" · "did you get home okay?".

now: richer curated feed · device reminders · RSVP sync (EventRSVP live) pods UI on EventPod live external feeds = Ticketmaster/Skiddle fn+creds

4 · Library / Book club

A reading life, together

Thin now: the shelf is basic; per-book "talk" is a generic corner; no buddy reads, no mood discovery, no reading progress.

Depth ideas

  • Mood/theme discovery shelves — "a warm hug", "twisty", "hopeful", "perimenopause memoirs beside swoony romance" (whole-life, never a health list up front).
  • Buddy reads — pair with a woman reading the same book, async, spoiler-locked (the BuddyRead entity is already added).
  • Reading progress + checkpoint-gated discussion — a thread unlocks only when you say you've reached it (spoiler-safe).
  • "Currently reading" as a gentle profile/presence chip; a proper Jess-hosted book of the month arc.
Nudges: "your book-club checkpoint is open" · "someone's reading your book too" · "your buddy left a note".

now: mood shelves · reading progress · Open Library search (live) buddy-read UI on BuddyRead · cross-device shelf on UserBook (live)

5 · Circles

Where it's believed — and alive

Nudges: "your circle's ritual is up" · "someone new joined TTC" · "a reply in Perimenopause".

8 · 1:1 / DM — SAFETY-CRITICAL

Being held, one to one

Thin now: the live 1:1 is the Witness path (one matched, anonymous, moderated, one-shot reply) — but with no proper explanation, no conversation drivers, no nudges. A richer free-text back-and-forth is designed but parked on a safety decision.

Depth ideas

  • Proper explanation + charter — what the 1:1 is, how matching works, the promises (anonymous, no location, moderated, block/report, not for crisis → routes to support).
  • Conversation drivers — "what would you like held?", suggested openers, a gentle structure so it's never a blank box.
  • Return nudges — "a sister replied", "your witness is holding space" (with strict anti-abuse rate-limits).
  • The richer free-text thread — an ongoing (not one-shot) exchange, still anonymous, still no location.

HARD RAILS (non-negotiable — ship these or don't ship)

  • 18+ gate (already app-wide).
  • NEVER share or ask for location — matched on season/life-stage only.
  • Server-side moderation BEFORE a message is delivered — every message is screened by a function before it reaches the recipient; harmful → blocked, never delivered.
  • Block + report on every message; crisis pre-check routes heavy content to support, never to a peer.
  • Do NOT ship half-built — the free-text thread ships only with all of the above.

now: explanation + conversation drivers + charter on the EXISTING Witness path (client)

FLAG — the free-text DM thread needs: a Message entity + a matched-thread entity + a moderation-BEFORE-delivery function (screens each message pre-delivery) + block/report. This is the sign-off item — do NOT build the thread without it.
