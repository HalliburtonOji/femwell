Held, one to one

Halli wants it to feel like WhatsApp — a conversations list, message bubbles, timestamps, a normal chat — but inside FemWell's brand and rails. That's the whole tension: WhatsApp feels instant, and our safety promise is that no message reaches a woman before it's been checked. This spec resolves that, and specifies exactly what to build. Nothing is built — this is for your sign-off. It ships only with every rail, never half.

The one-line thesis

A familiar chat that's anonymous by default (her botanical alias + presence bloom, never a name or location), opt-in only (request-to-chat — no cold DMs), and screened before delivery (a sub-second check so it still feels instant). Text-only at launch. Block, report or leave any time.

c · Onboarding / explanation (the missing piece)

First time she opens 1:1, a warm card — what it is · who she's talking to · how to stay safe:

"One to one, privately." You're talking with another woman here — anonymously (a flower and a name like "Wild Poppy", never real names, never your location). Every message is checked before it reaches her, so unkindness doesn't land. You can block, report or leave any chat, any time. This isn't for emergencies — if things are heavy, help is here (Samaritans 116 123 · NHS 111). 18+.

d · Conversation drivers + return nudges (the substance)

  • Icebreakers when you request a chat — a one-line context ("your post about work stress spoke to me") + optional starter prompts so it's never a cold blank box.
  • Gentle in-thread prompts when it goes quiet — "what would you like held today?" — never nagging.
  • Return nudges (rate-limited, no pressure): "a sister replied" · "your chat request was accepted" · "Wild Poppy is thinking of you".
3 · Starting + identity

How a DM begins, and who you are in it

How you start — REQUEST-TO-CHAT (recommended)

You can ask to chat from a post/comment that resonated, from "someone like you" resonance, or from a Witness exchange (turn a one-shot into an ongoing chat). You never cold-message anyone: you send a request (your alias + a one-line why), and a conversation only opens when she accepts. There are no public profiles to DM from (the app is anonymous).

Recommendation: mutual opt-in request-to-chat. It removes the single biggest harassment vector (unsolicited DMs), and it's warm — she chose to talk to you. Decline is silent (he/she never knows). Requests are rate-limited.

The anonymity model — reconciled

She chats as her botanical alias + presence bloom — the same veiled identity as the Talk rooms and her Bloomprint. Consistent, anonymous, no real name, no location.

Tier (Bloomprint)In a DM
Veiled (default)Alias + presence bloom only — "Wild Poppy". No name, no location. Launch default.
My flowerA richer bloom shown; still no real name.
Named (opt-in, per chat)A chosen display name (never real name / never verified identity) she may reveal in a specific trusted chat. Opt-in, reversible.

Recommendation: launch veiled-only (alias + bloom). Add the "named" (chosen-name) reveal later, per-conversation and opt-in — never a real-name or location reveal, ever.

4 · Safety — the heart of it

Instant feel vs "checked before it lands"

WhatsApp feels instant because it delivers immediately. Our promise is the opposite: a harmful message must never reach a woman. In a 1:1 the harm lands on one person, directly — so the "publish-then-hide" model we use for public posts is not acceptable here. We resolve it with a fast screen-before-deliver.

ApproachVerdict
Deliver-then-screen (instant, hide after)Feels instant — but the harm reaches her first. Rejected for 1:1.
Screen-before-deliver (a sub-second check, then deliver)Recommended. Feels near-instant + honours the rail.
Recommendation — screen-before-deliver, layered + fast: on send, the message goes to a server function that runs (1) an instant local crisis + keyword pre-check (0ms) and (2) the OpenAI Moderation API (free, ~200–400ms). Only on a clean pass is the Message created as delivered and it appears for her. Risky → auto-held, never delivered: the sender sees "this can't be sent as written — reword it", or crisis language → the sender is gently routed to support and the peer never receives it. The UX cost is a brief "sending…/✓" tick — which WhatsApp already has, so it reads as native, not slow.

HARD RAILS — non-negotiable (ship all, or don't ship)

118+ only — the whole surface sits behind the app's age gate.
2NEVER share or ask location — no location field, no "where are you" prompts; matching is season/life-stage only. (If a user types an address, the check can flag it.)
3EVERY message screened before/at delivery — server-side, before it reaches the recipient. No exceptions.
4Crisis → support, never a peer — heavy/self-harm content is not delivered to another woman; the sender is routed to Samaritans/NHS 111/Shout.
5Block · report · leave on every conversation; a blocked woman can never message you again; reports hide + queue for review.
6Request-to-chat (no cold DMs) + rate-limits (anti-spam/brigade) + new-account throttle.
7TEXT-ONLY at launch. Media/photos are a later, heavily-gated decision — image harassment and, critically, CSAM risk require hash-matching (PhotoDNA-class) scanning + legal reporting duties. Do NOT enable media in v1.

OSA 2023: a 1:1 messaging feature is a user-to-user service with illegal-content duties; a real UK legal review of the DM policy + safeguarding copy is required before public launch (not legal advice).

6 · Sequencing

Feasible now vs sign-off · phased

  • Phase 0 — buildable NOW (no backend): the explanation/onboarding + the charter + conversation drivers layered onto the existing Witness 1:1 (so today's 1:1 stops being unexplained). now
  • Phase 1 — the DM system (SIGN-OFF): request-to-chat + text DMs with screen-before-deliver + block/report/leave + the WhatsApp-style conversations list & thread. Text-only, veiled-only. needs the entities + functions above
  • Phase 2 — later, separate calls: typing/read affordances, "named" chosen-name reveal (opt-in per chat), maybe screened voice notes. later
  • Deliberately NOT v1: media/photos (CSAM + harassment gating), real-time presence, group DMs. gated / deferred

Recommendation: Phase 0 can ship immediately to fix the "no explanation" gap on the existing Witness 1:1. Phase 1 (the real WhatsApp‑style DM) waits on your explicit go on the sendMessage moderation‑before‑delivery function + the Conversation/Message entities — and ships only with all seven rails.
