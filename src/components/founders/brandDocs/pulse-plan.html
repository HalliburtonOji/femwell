2 · The frontier (cited, 2023–26)

The deeper evidence

Each row flagged evidence / popular-practice / myth/risk. Women-specific.

01The "28-day cycle" is a myth — only ~16% have one

In Flo's cohort (n≈1.58M) just 16.3% had a 28-day median; 91% fell in 21–35 days. → Anchor every prediction to her OWN median, never 28 — the single biggest honesty fix. evidence

Flo cycle-variability cohort (PMC)

02Predictions are decent, not infallible — show error bars

Pooled wearable cycle accuracy ≈0.88 but sensitivity/specificity ≈0.80 (~1 in 5 calls wrong); ML labelling of cycle-day-1 ≈61%, menses prediction ≈51%. → Present a window + confidence, never a single confident date. evidence

Wearable accuracy meta-analysis · ML cycle prediction 2025

03Ovulation roams — never a single certain day

In the landmark prospective study, the fertile window fell within the "textbook" days 10–17 in only ~30% of women; every day from cycle-day 6–21 carried ≥10% probability. → Ovulation as a probabilistic window, with a clear "calendar maths can't see late ovulation" note. evidence

Wilcox fertile-window study

04A model that learns the individual beats fixed averages

Bayesian/generative models that account for self-tracking gaps improve next-cycle prediction over naïve averaging; Clue openly predicts from the last 12 cycles and states stress/sleep/meds reduce accuracy. → Personalised, transparent model + honest caveats (copy Clue's transparency). evidence

Generative cycle model (JAMIA) · Clue method

05Cyclical symptom patterns are real — when logged forward

PMDD's gold standard is 2 cycles of prospective daily ratings (recall over-attributes); menstrually-related migraine is well-evidenced (peri-menstrual attacks differ measurably). → FemWell's forward-logged mood/symptom-by-phase is clinically meaningful; gate forecasts behind ≥2–3 logged cycles. evidence

PMDD prospective rating · Menstrual migraine e-diary

06Beware the pseudoscience — seed-cycling & rigid "cycle syncing"

Seed cycling has no scientific support; the largest review (78 studies) found cycle phase has trivial effects on exercise performance and no evidence for "phase-based productivity". → Offer gentle phase awareness (ease off on the heaviest days), never deterministic "do X on day Y" prescriptions. myth

Seed cycling (Sci-Am) · Cycle-syncing & exercise (Clue)

07Insight must be interpreted — chart-dumps stall people

Personal-informatics research: raw data strands users at "reflection"; the system must do the interpretation. → Ship insights ("your mood tends to dip late-luteal"), not chart-walls — exactly Pulse's "what your body repeats" framing. evidence

Lived informatics (HCI) · Health-viz guidance (JMIR 2024)

08n-of-1 correlations are noisy — guardrails are mandatory

Individuals rarely run valid self-correlations; naïve correlation invites false discovery. → A correlation engine needs a minimum-data gate, restrained multiple comparisons, a confidence note, and an explicit "a pattern, not a cause" line on every card. risk

Self-experiment validity (NSF)

09Over-tracking can become anxiety ("orthosomnia")

Clinicians report patients fixating on wearable "scores", chasing perfect numbers — a named harm. Sensitive cycle data raises the stakes. → Gentle narrative default, "patterns not scores", and a dial to turn detail down. risk

Orthosomnia / quantified-self harm

10Wearable physiology by phase is real (with caveats)

Wrist temp gives a retrospective ovulation estimate (~1.6-day error); resting HR rises ~2–7 bpm follicular→luteal (WHOOP +2.73); HRV declines into luteal. PPG wrist data is noisier than chest straps. → Surface temp/RHR/HRV by phase as trends with a reliability note; never a contraceptive claim (that's Natural Cycles' regulated turf). evidence

Wrist-temp ovulation (Hum Reprod) · WHOOP RHR

11Irregularity is the perimenopause signal — and clinically actionable

NHS: a change in your normal pattern is often the first perimenopause sign; report bleeding >1 week, more often than every 3 weeks, or any bleed ≥12 months post-period. → A "this cycle is different" flag that routes to NHS thresholds (never diagnoses) is the highest-value, lowest-risk feature. evidence

NHS irregular periods

12Cycle data is special-category — privacy is a differentiator

Reproductive-health data is "special category" under UK GDPR Art. 9 (explicit consent, higher protection); post-Roe, women actively delete trackers over US data-transfer fears, and audits flag UK femtech data going to the US. → Local/anonymous-first processing, opt-in imports, data minimisation — a trust moat, not overhead. evidence

Period-app privacy (EDRi) · Flo Anonymous Mode

13Competitive teardown — where rivals stop

Clue: transparent prediction method, honest caveats — but no physiology, no correlation engine. Oura/Apple/Natural Cycles: strong temp/HRV/RHR physiology + retrospective ovulation — but life-context-blind, and Oura needs a £300 ring. WHOOP: phase into recovery, athlete-framed. Bearable: the only real cross-factor correlation engine (caffeine/sleep/work vs mood/pain) — but generic, non-cyclical, and weak on causation caveats. market

Clue · Oura Cycle Insights · Bearable

Every rival is either cycle-strong but life-blind (Clue/Oura/Apple/Natural Cycles) or correlation-capable but generic and causally careless (Bearable). 5 · The one gated call

Real wearable import needs your OK

Almost all of +1/+2 is client-side statistics or rides the existing Jess agent — no new function. The forecasting, correlation engine, anomaly flag, own-median model and retrospective are all computed from data you already hold.

  • Why import may need a function: Base44 is a web app — it can't read Apple HealthKit directly, and pulling Oura/Garmin means an OAuth token exchange + API call, which wants a small server function (and stored device tokens). That's the one capability that touches the "no new function" rule.
  • The no-function fallback: a manual Apple Health / CSV export import (the user uploads their export) populates WearableSync with zero new function — less magical, fully rule-safe, a fine v1.
  • If you approve the function: a single capped device-sync function (OAuth + periodic pull), opt-in, minimised, with explicit consent (special-category data, §12); never a medical/contraceptive claim.

Flag: this is the only item that may need a new gated capability — and it has a real no-function fallback. Everything else ships rule-safe. Recommendation: ship the correlation/forecasting/anomaly intelligence first (no gate), then decide import.

7 · Honest build reality

What's rule-safe vs what needs a call

  • Rule-safe (no new function): own-median prediction + error bars, predicted-symptom forecasting, "this cycle is different" anomaly flag (NHS-routed), anxiety-safe dial, correlation-discovery engine + life-domain trends (client-side stats with guardrails), "year in patterns" retrospective, clinician export (rides Doctor Export), manual wearable CSV import. Small additive entities only (e.g. a forecast cache, a "framing" preference).
  • Needs your OK (one function, with a fallback): live device import via OAuth/API (§5) — or ship the manual-import fallback with zero rule-risk.
  • Privacy must-haves: opt-in imports, data minimisation, explicit consent for special-category data (§12).
  • Avoid: any contraceptive/diagnostic claim (Natural Cycles' regulated turf), deterministic "do X on day Y" prescriptions, raw-score gamification.
