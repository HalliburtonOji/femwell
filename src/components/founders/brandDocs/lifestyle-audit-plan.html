Lifestyle — deep audit + redesign & substance plan

Plan-first pass (no live Lifestyle code changed). Same treatment we gave Community and Nutrition: bring the page onto the canonical §6.8.2 template and deepen every feature. Code-trace audit of the live shell + every sub-surface, entity and function. 2026-07-14.

TL;DR

The live Lifestyle page (LifestyleEliteShell) is good but a generation behind. It was flipped live on 2026-06-28 to the older §6.8 v1 signature (hero → SummaryCard → boards). Nutrition and Community were later rebuilt to the newer §6.8.2 canonical template (2026-07-08): flora hero + tap-to-rebloom controller cards → glance ⇆ Jess sliding row (a rotating per-page Jess digest with an upward inner sheet) → boards → “Handy right now” quick row → closing. Lifestyle is missing bands 1(controller cards), 2 and 4.

Bigger than the shape: the page is starving its own backend. A full personalisation engine (getLifestyleFeed + LifestyleProfile + LifestyleInteractions + recordLifestyleAction) already exists and is completely unwired — “Picked for you” is really just top-engagement_score. Two of the app’s richest readers — the immersive Kindle-flip Daily Story reader and the ~15-section Horoscope reader (with birth-chart onboarding) — were dropped when the Elite shell re-implemented those surfaces inline, and are dark in production. Almost every fix below is feasible now with the code and functions that already exist; new backend is rarely needed.

The 5 boards, and what each holds today

  • The good life — a “what do you have time for?” dopamine-menu (3 time bands → a read + a listen + a make/awe prompt) + a “permission to enjoy it” lens (static slips + “book a quiet hour”). Genuinely novel; the picks are real, the permission copy is static.
  • For you — Editor’s pick + more · Saved · Try this · For your phase. Real data, but not personalised (top engagement only); Try this = 3 hardcoded prompts.
  • Read — Articles · Stories · Books (today’s chapter + FemWell fiction + Gutendex public-domain) · Guides. Articles/Stories/Books real; Guides mostly a static fallback.
  • Listen — Podcasts (real <audio> player) · Videos (inline youtube-nocookie) · Trending TikTok (link-out) · External pods (2 static). Player works; the video/podcast content itself is nearly all placeholder (see §3).
  • Story & sky — Daily story (static excerpt) · A day for you (1 title + 4 alts, hardcoded) · Horoscope lens · Sky diary (real SkyNote persistence). Sky diary is real; the story + horoscope are thin shadows of the real readers.

Persistence that does work today: Save → UserProfile.saved_item_ids; Sky diary → SkyNote; A day for you / Try this → PlannerItems (wellbeing). All optimistic + rollback + toast.

2 · Where it’s thin, off-brand, or broken

headline gap The personalisation engine is unplugged. The shell reads LifestyleItems.filter({status:"PUBLISHED"}, "-engagement_score", 60) — a flat popularity sort — and has zero references to getLifestyleFeed, LifestyleProfile, LifestyleInteractions, or recordLifestyleAction. Those functions/entities already exist and work (followed topics/sources, hidden ids, like/save/hide → category weights, cycle/energy boosts). So “Picked for you” and “For your phase” aren’t actually tuned to her, and her taps teach the system nothing.

dark in prod Two of the app’s richest readers were dropped.

  • Immersive Daily Story reader (DailyStoryReader.jsx, ~2,000 lines: measured pagination, 3D page-flip, movie mode, themes, bookmarks, cliffhanger countdown). The Elite shell replaced it with a static ChapterSheet excerpt of segment_text. The rich reader now survives only inside Fiction/Book readers.
  • Full Horoscope reader (HoroscopeTab.jsx: Triad sun/moon/rising, GoddessBench, CycleMoonDial, RedWhiteMoon, AnnualProfections, Compatibility, AskTheSky, QuietMode, … ~15 sections, real generated readings). The Elite shell shows only a small HoroscopeLens + ReadingSheet. Worse: BirthDataSheet (birth-chart onboarding) isn’t imported in the Elite shell, yet the ReadingSheet tells users to “add birth details on the Horoscope tab” — a tab that isn’t mounted. New users may have no way to set up their chart on the live page. (Worth a 30-second live confirm; inferred from imports.)

content gap No real video, thin real audio. src/data/lifestyleVideos.js is 6 hardcoded YouTube clips, and its own header notes the live items carry no media URLs — so those 6 are effectively the whole Videos lane, and real videos link-out rather than play. External podcasts are a static curated list. The ingestion + summarise pipeline exists (ingestYouTubeChannels, summarizeLifestyleItem) but isn’t populating playable media.

stale copy Hardcoded lenses that should breathe. Try this (3 static), Guides (static fallback), External pods (2 static), TikTok fallback (3 static), A day for you (1+4 static), Permission slips (static). None rotate; none are signal-driven. On a template whose Jess digest is supposed to change every load, these read flat.

whole-life Too cycle-tinted for a whole-life room. Lifestyle is FemWell’s most life-spanning surface, but the picks lean health/cycle (phase picks, “cycle-syncing” guides). The LifestyleItems.category enum has 27 values — the life domains (relationships · dating · friendship · career/money · fashion/beauty · creativity · joy · entertainment · venting/“gossip”) are under-surfaced. Let life-stage tint, not dominate (CLAUDE.md).

latent bug Today’s Daily-Story reel deep-links are stale. DailyStoryReel.jsx (on /Today) routes to legacy ?tab=daily_story&open= / ?tab=for_you&open= contracts the Elite shell doesn’t consume — so a tap lands on the Lifestyle page’s default state, not the intended chapter/item. Cheap fix once the shell honours an ?open=/chapter param.

5 · Recommended build order (one feature at a time)

  1. Structural rebuild → LifestyleV2Shell (§6.8.2). Port controller cards + JessGlanceSwipe/JessCard + lifestyleJessSummary + V2QuickRow from Nutrition/Community; keep all 5 boards and every real surface. Biggest visible win; no backend. Flip pages.config only after Ms Verify passes (one-line revert kept). now
  2. Wire real personalisation. getLifestyleFeed for Picked-for-you + phase picks; recordLifestyleAction on every save/open/hide. The feed starts learning. now
  3. Restore the immersive Daily Story reader + fix the Today reel deep-links. Crown-jewel reading experience back on the live page. now
  4. Restore the full Horoscope reader + birth-chart onboarding as the Sky door. Rich daily surface + fixes the onboarding dead-end. now
  5. De-hardcode the lenses & go whole-life. Rotate Try this / A day for you / permission / external pods per load; add life-domain filter chips to Read/Listen/For-you. now
  6. Fill the real media lane. Run the ingestion + summarise pipeline so videos/podcasts actually play; review to PUBLISHED. Content-ops, existing functions. backend/ops

Steps 1–5 need no new backend. Each is a self-contained, shippable pass with its own Ms Verify gate; deploy + STATUS entry per step.

6 · Feasibility, entities & the function cap

Entities — all needed ones already exist: LifestyleItems, DailyStory, HoroscopeReading, SkyNote, PlannerItems, LifestyleProfile, LifestyleInteractions, AstroProfile, UserProfile. No new entity required for steps 1–5.

Functions to reuse (no new ones): getLifestyleFeed / rankLifestyleFeed / recordLifestyleAction (personalisation), generateHoroscopeReading / askStars / generateCompatibility (sky), ensureDailyStoryPack / storyWorker / generateNextStoryItem (story), expandContent (article body), fetchGutenbergBook (books), ingestYouTubeChannels / summarizeLifestyleItem (media, step 6).

Target: zero new functions. Every substance idea above rides an existing function or is pure front-end.
